## Findings

| # | Area | What exists today | Impact on the design |
|---|---|---|---|
| F1 | **Result storage (R1)** | Four storage shapes: `CountTestReading` (count, per step), `Result` + `PathogenObservation`/`WorkflowStepResult` (observation chain), `HplcAssayResult` (one active row per test order, replicates as jsonb), and `ElementalAssayEntry` + `ElementalAssayResult` (one entry per order, **one result per (TestOrder, Specification)**, calculation snapshot columns, IsActive, signature). | The elemental pair is already the shared foundation the prompt asks about: an order-level entry (common inputs, signature) + per-parameter results. Generalising it (entry = "analysis", result = "parameter result", readings as child rows) covers every type below. |
| F2 | One-result-per-test assumptions (R1) | Per-type branches exist in: `SampleApprovalService` (HPLC + elemental gates, ~150-175), `ReviewService.ReturnToAnalystAsync` (Count/HPLC/Elemental only, refuses others), `ResultProjectionService` (one Upsert per source table), `SampleSummaryService` (HPLC detail, elemental detail, export text blocks), `coaAggregation.ts` (HPLC one row; **elemental already one row per element**), `SampleSummaryDialog`/`TestResultCards` (per-type blocks), `isTestOrderNonPassing`. | Each new result table today means edits in ~8 places. A single generic result foundation reduces it to one branch each. Places that already cope with several parameters: elemental summary/CoA, `FormatSpecificationsText`, `SpecificationLookup` (primary parameter). |
| F3 | Workflow routing (R2) | `WorkflowType` {CountTest, Observation, HplcAssay, ElementalAssay} is a hard-coded enum; `TestWorkflowDialog` routes by `current.workflowType` to a panel (`HplcAssayPanel`, `ElementalAssayPanel`) or the generic step UI. `EquationType` {None, HplcAssay, SystemSuitability, CalibrationCurve}; `masterdata/equation-types` returns a hard-coded list. MasterDataController validates pairs (HplcAssay equation needs HplcAssay workflow; CalibrationCurve needs ElementalAssay). FP Test Master offers {HplcAssay, ElementalAssay}; Micro page {CountTest, Observation}. | Add WorkflowTypes per **entry shape**, not per chemistry: see build spec (Measurement, Gravimetric, Qualitative, UnitTimed, ExternalStandardAssay (HPLC+UV), Dissolution, DosageUniformity, Titration). |
| F4 | Observation workflow reuse (R2) | `Observation` = "staged pathogen detection chain, driven by each step's StepType" (WorkflowType.cs) - incubation steps, media, TSB; section scope code treats it as Micro (UserSectionScopeService:226). | **Not reusable** for appearance/ID. Qualitative needs its own light workflow (observed text + conforms/does not conform). |
| F5 | HPLC calculation (R3) | `TestWorkflowEngine.RecordHplcAssayResultAsync`: per replicate `% = (area/StdMeanArea) × (StdWt/SampleWt) × (Purity/100) × (SampleDil/StdDil) × 100`, mean of replicates, compared **unrounded** via `SpecificationEvaluator` (primary spec), displayed `Math.Round(mean,1,AwayFromZero)` + " %". Standard values are snapshotted from the linked `SystemSuitabilityRun`; the suitability gate is applied when linking (passed run of the same method + section) and again at recording. | The formula is detector-neutral: "area" = response. UV assay = same engine with response = absorbance and a different validity record. Rename conceptually to External Standard Assay; keep HPLC behaviour byte-identical. |
| F6 | Standalone records (R4) | `SystemSuitabilityRun`: code `{ABBR} S.S nn/MMyyyy`, signed once, immutable, Passed computed at creation, no withdrawal, no attachment. `CalibrationRun`: code `{ABBR} CAL nn/MMyyyy`, signed once, mandatory hashed attachment, per-analyte gate, preview, one-way signed withdrawal, `IsUsable`, lab-local time. Both use `SystemSuitabilityRunCode` (infix param) and `ILabClock`. | Common pattern is proven twice. A shared **"validity record"** base (code/infix, method, section, instrument, signature, status Active/Withdrawn, CalibrationAt-style "performed at", validity window, attachment optional) fits UV suitability, titrant standardization, KF titer and the dissolution apparatus check (G4). |
| F7 | Equipment (R7) | `EquipmentType` {Incubator, Autoclave, LafCabinet, BiologicalSafetyCabinet, WaterBath, Other, Hplc, PhMeter, Balance, IcpOes}; `Equipment.CalibrationDueDate` (comment: incubator-only). `EquipmentInventory` has CalibrationDueDate, Status {InService, OutOfService, Retired} and computed `IsCalibrationOverdue` - documented as display-only, "nothing in the workflow engines reads from it". **No calibration gate anywhere.** Lab list (physico-chemical): UV-Vis Varian Cary 50; HPLC ×4 (+1 R&D); ICP-OES PerkinElmer; **AAS Varian SpectrAA**; **GC Shimadzu**; dissolution Electrolab; disintegration Pure Enterprise (listed twice, same code DST-F-WL-F-01-040); Karl Fischer ×2 (Spectra lab; Metrohm Tiamo); potentiometric titrator Metrohm Tiamo; viscometer Brookfield; refractometer Optika; polarimeter Anton Paar; pH ×2 + pH/TDS/conductivity Adwa; melting point Stuart; oven, drying cabinet, muffle; digestion microwave; caliper, micrometer, X-Rite (packaging lab). **No hardness tester and no friability tester on the list.** | Add equipment types for what exists (G8). An "instrument calibration current on the analysis date" gate is new work (inventory is not linked to workflows) - propose as an optional slice. Friability/hardness equation modes can wait until the lab confirms the instruments. |
| F8 | Materials and solutions (R8) | `Material`: Purity (6,3, required for ReferenceStandard), ExpiryDate (nullable), SectionId, computed Status {InStock, Depleted, Expired} / IsUsable, `MaterialType` {DehydratedMedia, LyophilizedMicroorganism, Supplement, AntibioticDisc, IdentificationKit, IdentificationReagent, Chemical, Indicator, ReferenceBuffer, DisposableTool, Other, ReferenceStandard}. **Purchased stock only** - no concentration/normality/titer/prepared-date/in-use validity. | Reference and primary standards: yes (ReferenceStandard + Purity). Titrants/KF reagent: purchased lot yes, **standardized value no** - the normality/titer must live on a standardization record (F6), not on Material. Dissolution media: not tracked (record composition as text on the apparatus record). |
| F9 | Staged evaluation (R5) | Universal Specifications: `LimitType.MultiStage` with `SpecificationStage` rows (StageNumber, StageLabel, AcceptanceCriteriaText) - **descriptive text only**; `SpecificationEvaluator.Evaluate` throws for MultiStage/Qualitative/PresenceAbsence. No stage state anywhere. | A staged engine is new: typed stage criteria (dissolution Q, UDU L1/L2 + k, disintegration unit counts/time) + stage state on the result (current stage, units tested, outcome). One engine can serve dissolution, disintegration and UDU because all three are "n units -> rule -> pass / escalate with more units / fail" (G3). |
| F10 | Multi-unit entry UI (R6) | `LocationResultGridDialog` (dynamic rows, nested replicate inputs, live client-side thresholding - page-specific), `MultiSampleEntryGrid` (reusable table container, `(index, field, value)` change model, no keyboard nav, no paste), `HplcAssayPanel`/`ElementalAssayPanel` (1-D replicate list). None supports paste or arrow-key navigation. | Build one reusable `UnitEntryGrid` (fixed N rows, 1-3 numeric columns, paste a column from Excel, Enter/arrow navigation, no client calculation) - used by measurement replicates, dissolution vessels, UDU units, weight variation, disintegration. |
| F11 | Specifications (R9) | LimitType {Range, NMT, NLT, TargetWithTolerance, CountTiered, Qualitative, PresenceAbsence, MultiStage}; `Specification` also has ResultBasis, LabelClaim(+Unit), ConversionFactor, SampleMatrix, TestAnalyteId (elemental). Canonical SpecLimit text keeps legacy readers working. | Numeric types reuse Range/NMT/NLT/Target. Qualitative reuses Qualitative/PresenceAbsence. New typed criteria needed: evaluation basis for replicates (mean/each/min/max), dissolution Q + stage profile, UDU L1/L2 (+ k per n), weight-variation bands, disintegration time limit. ResultBasis/LabelClaim/ConversionFactor reused by UV and titration assays. |
| F12 | Units and conversions (R10) | Unit is free text on `Specification.Unit` (and snapshotted on results). ConversionFactor exists (elemental). No IU ↔ µg or salt ↔ base catalogue. | Reuse ConversionFactor for salt/elemental and IU conversions (factor entered per item assignment, e.g. 0.025 µg per IU for vitamin D3) - no unit master this round. |
| F13 | Rounding (R11) | Counts: `Math.Round(..., AwayFromZero)` to whole CFU for display; `<1` rule. HPLC: compare unrounded mean, display 1 dp AwayFromZero. Elemental: compare unrounded, display 1 dp. Sample-summary export trims Postgres scale. No per-spec decimal setting. | Propose one rule (G6): `Specification.ReportDecimals` (default = decimals of the limit as written) and `RoundBeforeCompare` (lab decision; USP GN 7.20 = true). Until decided, keep "compare unrounded". |
| F14 | CoA / summary (R12) | CoA simple rows are one per test, except elemental (one per element). Sample Summary has per-type blocks with calculation detail (HPLC, elemental). | Multi-reading types show one CoA row per parameter with the reported value (e.g. dissolution "S1: min 86 %, mean 92 % - Complies"), and the full reading table (vessels/units/weights) in the Sample Summary and export, not on the CoA. |
| F15 | Permissions / scope / audit (R13) | Result entry: `PermissionConstants.TestWorkflowExecute`; approvals: `SamplesApprove`/`SamplesReview`; master data: `[Authorize(Roles = SectionHead, SystemAdministrator)]`; run withdrawal: `SamplesApprove`. Section scope via `IUserSectionScopeService` (`Ensure*AccessAsync`, per record type). Audit is automatic (`CaptureAuditEntries`); signatures via `IElectronicSignatureService` (append-only table - sign against a stable entity, set the navigation). | No new permission codes needed. Each new validity record needs its own `Ensure...AccessAsync` + `UserReferenceRegistry` entries. |
| F16 | Test infrastructure (R14) | xUnit InMemory unit tests + `PostgresFact` integration tests (`MICROLIMS_TEST_POSTGRES`), `TestServiceFactory`, fake `TimeProvider`/`ILabClock` (calibration tests), decimal boundary tests (TC5, TC13, TC14). agy-generated Postgres tests have repeatedly been wrong (seeded unsigned runs, recorded on reviewed orders) - they must be run, not assumed. | Staged engines are pure functions of (criteria, unit values) -> table-driven decimal tests per stage boundary; one Postgres end-to-end per type. |
