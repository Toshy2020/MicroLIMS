# ChemStation C.01.07 file-drop / edge-agent proposal — review against the MicroLIMS codebase

Review-only. No code, migrations or config were changed. All paths are relative to the repo root; `backend/` paths are abbreviated (`Persistence/…` = `backend/MicroLIMS.Persistence/…`, etc.). Line numbers are from branch `docs/user-guide`. Items I could not confirm from code are marked **[UNVERIFIED]**. Nothing here is described as "validated" or "verified" — this is a design critique grounded in the current source, not a validation record.

---

## 1. Summary verdict

The ingest-never-accepts principle (point 4) and the "reuse the existing review workflow" stance fit MicroLIMS well, but the proposal as written ignores that **an HPLC run domain already exists** (`HplcRun`, `HplcRunSample`, `HplcSampleReplicate`, `HplcReplicateResponse`, `HplcEvidence`, plus `HplcMethodAssayRecorder` for signed submission). A parallel `InstrumentRun`/`InstrumentRunVersion`/`PeakResult` family would duplicate it and create two sources of truth for "the HPLC run". The biggest conflicts are: (a) no service/machine identity exists — the whole auth and audit stack assumes a human `User` row with one of four `RoleType`s, and an unattributed request is audited as `UserId = 0`; (b) the edge agent parses reports, which breaks "logic lives in the backend" and bypasses the `IFileStorageService` seam; (c) the proposal's decimal premise (EF default `decimal(18,2)`) is a SQL Server fact, not true on this Npgsql stack; (d) `DateTimeOffset` and `/api/v1/…` do not match repo conventions, and "Instrument" does not match the domain word (`Equipment` / `EquipmentInventory`), which are two unlinked tables with the serial number only on the wrong one. Recommended direction: keep the agent but make it a dumb, authenticated **file courier** (hash + raw upload + outbox); parse server-side from the stored original with the existing `InstrumentImport` pattern; land the result as **evidence + proposed values on the existing `HplcRun` flow**, with an analyst confirming the match and signing through the existing `HplcMethodAssayRecorder` submit.

## 3. Answers to the open questions

### Q1. Does an Instrument master-data entity exist? If not, what would it depend on?

No entity named Instrument. Two related ones, not linked:

- `Equipment` (`Domain/Entities/Equipment.cs`): `Code`, `Name`, `Type` (`EquipmentType.Hplc` exists), `Vendor`, `CdsSoftware`, `ConnectionSettings` (jsonb), `SectionId` → `DocumentSection`. It is what `HplcRun.EquipmentId` references. **No serial number.**
- `EquipmentInventory` (`Domain/Entities/EquipmentInventory.cs`): asset register with nullable `SerialNumber`, `FirmwareVersion`, `CalibrationDueDate`, `Status` (`InService/OutOfService/Retired`), `SectionId`; unique only on `Code`. The class header states workflow engines do not read it.

Anything that resolves an instrument for ingest depends on: `DocumentSection` (lab segregation; `Equipment.SectionId`), `EquipmentType.Hplc`, `CdsSoftware`, and a **new, audited link** between the HPLC `Equipment` row and its inventory/serial. I did not find that link in code; I did not verify whether the ChemStation HPLC has an `Equipment` row today (docs say it did not as of 2026-09-19).

### Q2. Which existing identifier should the ChemStation Sample ID map to?

Not a single one:

- For a product/RM/PM sample: `Sample.ReferenceNumber` (unique, system-generated, ≤20 chars; `Sample.cs:13`, `SampleConfiguration.cs:12-13`). `BatchNumber`/`ControlNumber` are not unique and can span samples.
- But the regulated unit is the **test order replicate**: `HplcRunSample` (→ `TestOrderId`) → `HplcSampleReplicate.ReplicateNo` → `HplcReplicateResponse`. So the ChemStation name must encode *sample reference + replicate* (or be chosen from a list the analyst confirms).
- Standards and SST injections are not `Sample`s: map to `HplcSstRecord.Code` / `HplcSstInjection.InjectionNo` and `WorkingStandardQualification`.
- Anchor option: put `HplcRun.Code` (unique, `HplcRunConfiguration.cs:17`) in the ChemStation sequence name so the run is identified first and injections are matched within it.

Matching should only **propose**; the analyst binds. What naming convention the lab actually types into ChemStation is not in the code (Q1 in §5).

### Q3. How exactly would ingestion hook into the existing audit trail?

Three existing pieces, used for different things:

1. `IAuditEventService.RecordSystemEventAsync(systemProcessName, actionCode, AuditActionCategory.ImportExport, recordType, …, changes, entityId, correlationId)` — `ActorType.System`, `UserId=null`, EVT-sequence id (`AuditEventService.cs:77-132`). Use for the "ingest received / version created / superseded / quarantined" events. Agent identity has no dedicated column (only `SystemProcessName`, ≤150 chars); adding an agent actor type is a Domain change and a decision.
2. Automatic `SaveChanges` capture (`MicroLimsDbContext.cs:270-300,307-377`) will still fire for the new entities unless excluded. It writes `UserId = 0` when no user is on the context (`:366`). Plan for it: either accept volume (finding 13) or capture at aggregate level with a documented rationale; do not exclude GxP raw rows silently.
3. Reviewer/analyst confirmation and sign-off: `ElectronicSignature` + `ReviewWorkflowEvent` through the existing HPLC submit path (finding 24).

The `AuditLog` table itself is protected by DB triggers (`20260902181230_AddAuditImmutabilityTriggers.cs`).

### Q4. Does the existing auth stack support a non-human agent identity?

No.
- Single JWT bearer scheme (`JwtAuthenticationExtensions.cs:19-24`); login-issued tokens only (`Infrastructure/Authentication/JwtTokenService.cs`, `Controllers/AuthenticationController.cs`).
- Every request is re-validated against a `Users` row, role and password-change time (`AccessTokenRevalidator.cs:32-75`).
- Four roles only (`RoleType.cs`); permission claims come from role grants (`PermissionAuthorizationHandler.cs:13`); unknown policy names are not resolved (`PermissionPolicyProvider.cs:25-37`).
- No API-key or client-certificate handling found. Rate limiting is configured for the anonymous client-error endpoint only per its header comment (`API/Extensions/RateLimitingExtensions.cs:~98`).
- Audit attribution assumes an integer user id (`AuditMiddleware.cs:19-24`), else user 0 (`MicroLimsDbContext.cs:366`).

## 4. Proposed changes to the design (design-level only)

1. **Re-scope the agent to a courier.** It watches, waits for stability, hashes, uploads originals (report + manifest), keeps an outbox. It does not parse, classify, or decide. Parsing is server-side, versioned, from the stored original, following the `InstrumentImport` seam.
2. **Land on the existing HPLC domain.** Replace `InstrumentRun`/`PeakResult` with: a thin ingest/receipt record + raw-file manifest, and injection/peak payload that *proposes* values for `HplcSstInjection`, `HplcReplicateResponse`, `HplcEvidence`. One run concept in the system (`HplcRun`), including for ICP symmetry (`IcpRun`).
3. **Storage through the port.** Decide explicitly: backend-mediated upload via `IFileStorageService` (needs hash recording and non-overwrite semantics added to the port or a sibling port), or externally held originals with server-recorded hashes and a documented retrieval SOP. Not a silent side channel.
4. **Agent principal is its own thing.** Separate agent table (IsActive, key hash, equipment link, section, registered/revoked by + reason, last seen), distinct permission/policy, registered in the authorization matrix test. Key issue/rotate/revoke = audited admin events (Part 11 §11.10(d), (g) access control; Annex 11 §12).
5. **Explicit system audit event per ingest** (category `ImportExport`) carrying agent id, manifest hash, report hash, equipment, and resolution outcome; decide peak/file row audit granularity deliberately.
6. **Supersession needs a human reason.** Reintegration/new report → new version, prior version flagged, `SupersedeReason` + confirming user required (mirrors `SupersedeEvidenceAsync`). Quarantined records get resolved by a signed action, never auto-promoted.
7. **Idempotency scope and race handling.** Unique index on (equipment/agent, run identity, report hash); use the existing unique-index retry helper; define "same hash, different identity" explicitly.
8. **Time model.** `DateTime` UTC like the rest of the repo; record server-received time from `ILabClock`; store the *as-exported local string* verbatim, plus resolved UTC and the zone used; record agent-reported clock and server clock at receipt so drift is visible; reject or quarantine on drift beyond a configured limit. DST fold/gap need a defined handling.
9. **Decimal rationale corrected.** Store verbatim text + parsed decimal with `HasPrecision(28,10)` for convention; the stated "default 18,2" reason is not true on Npgsql here. Parse with invariant culture and record the detected format.
10. **Append-only protection** for manifest/payload/version tables via the same DB-trigger approach used for `AuditLogs` if they are to be treated as raw-data records.
11. **Per-equipment configuration as master data** (watched folder, zone, accepted export format, parser version) with signed changes, not agent-local files.
12. **Conflict policy between typed and ingested values** (block / flag / reason) and a reviewer-visible diff — otherwise manual transcription risk remains.
13. **Drop `/api/v1` and Minimal-API assumptions;** follow controller + `ApiResponse` style. Add `Hplc`-style permission code and update `authorization-matrix.txt`.
14. **Defer Phase 2** (LIMS-generated sequences). Writing to the instrument PC is a different validation burden.
15. **Naming:** `Equipment`, `HplcRun`, injection, replicate, evidence — not `Instrument*`. State ingest-state values in a new enum with a names-never-change test, and keep them distinct from `ResultStatus`/`ApprovalStatus`.
16. **Coordinate with existing work:** `feat/instrument-report-ocr` / folder-watch intentions in project memory (`empower-report-ocr.md`) — confirm owner and overlap before building.
