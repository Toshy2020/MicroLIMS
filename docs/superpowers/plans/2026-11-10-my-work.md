# My Work (C1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One landing page listing everything waiting for the signed-in user, grouped and ordered by urgency, where each row opens the exact step, plus self-assignment of unassigned tests.

**Architecture:** A `MyWorkService` runs a set of independent `IMyWorkSource` classes (one per kind of task) and merges their items into ordered groups; a failing source is reported, not fatal. Sources reuse the existing queue predicates (`SampleWorkflowQueues`, `SectionReviewQueues`, `TestReturnHelper`) so My Work cannot disagree with the workspaces. The frontend page maps each item's typed `target` to a route.

**Tech Stack:** .NET 10, EF Core 10, PostgreSQL, React 19, MUI 9, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-my-work-design.md`

## Global Constraints

- `CLAUDE.md` binds every task (separate contexts + `AsNoTracking`; `[PostgresFact]` executed, 0 skipped; `userEvent`; mock only `services/`; no `any`; injected `TimeProvider`).
- Every source query is read-only, `AsNoTracking`, projected with `.Select`, section-scoped in SQL through `IUserSectionScopeService.GetReadableSectionIdsAsync`; no query inside a loop.
- Each group returns at most 50 items and an exact `count`.
- "Mine" always means the caller's own user id. `Sections.ViewAll` widens what can be **read** in section queues; it never makes another analyst's assigned test "mine".
- Urgency, due times and "today" are computed on the backend from `TimeProvider` and `LabClock` (`Lab:TimeZoneId`). The frontend never computes them.
- One "ready to read" rule: `SampleWorkflowQueues.IsIncubationReadyToRead`.
- Settings: `myWork.lookAheadDays` = 7 (1–30); `myWork.readOverdueHours` = 0 meaning off (0–168); `workflow.selfAssignment.enabled` = true.
- New permission `Tests.SelfAssign`, granted to the Analyst role through `RoleGrantSql` in migration `AddTestsSelfAssignPermission`.
- Group keys and titles (exact, in order): `readyToRead` "Ready to read now"; `returned` "Returned to me"; `endingToday` "Incubation ending today"; `toPerform` "Tests to perform"; `review` "Awaiting my review"; `approval` "Awaiting my approval"; `available` "Available in my section"; `unassigned` "Unassigned tests"; `documents` "Documents"; `equipment` "Equipment"; `materials` "Media, solutions and strains".

## Review Focus

1. **A user in two laboratories.** With `?lab=MICRO` no physicochemical item may appear, and the summary badge must equal the sum over both labs. Test in Task 2.
2. **A reviewer who is also the assigned analyst on one test of a multi-test sample.** The whole sample row is locked and uncounted, matching what the decision endpoint will do. Test in Task 3.
3. **Two analysts press Take within the same second.** Exactly one succeeds; the other gets the "already taken" message and no audit row. Test in Task 4.
4. **A source throws.** The other groups still arrive, the failed key is listed, and the summary endpoint reports "unknown" instead of a wrong smaller number. Test in Task 1 and Task 6.
5. **Local midnight in a non-UTC laboratory.** An incubation due at 23:30 lab time is "Today"; one at 00:30 next day is "Later", regardless of the UTC date. Test in Task 2.

A source exception is caught per source, sent to `IErrorCaptureService.CaptureAsync`, and its `Key` added to `UnavailableSources`; `OperationCanceledException` is not caught. Summary: if any source fails, `Total/Overdue/Now` are null and `Complete` is false.

HTTP: `POST api/testorders/{id}/take`, `POST api/testorders/{id}/release`, policy `TestsSelfAssign`. Take checks, in order: setting on → test exists and readable → unassigned, not superseded/cancelled/outsourced → caller is a member of `TestOrder.SectionId` (`EnsureAssignableAsync` with `assigneeId == actingUserId`) → save under the `xmin` concurrency token. Release: caller is the assigned analyst **and** the last assignment audit row for this test was a take by the caller **and** nothing is recorded (no rows in `Results`, `CountTestReadings`, `PathogenObservations`, `WorkflowStepResults`, `TestAnalyses`, `Incubations`, `SamplePreparations` by this user for the sample); otherwise "This test can no longer be released.
