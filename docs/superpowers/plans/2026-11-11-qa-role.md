# QA Role (B4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independent, read-everything QA system role that approves controlled documents and performs and signs audit trail reviews and access reviews.

**Architecture:** `RoleType.Qa = 5` with grants added by one data migration (the `AddQcManagerRole` pattern). Independence is enforced in `SegregationOfDutiesRules` (shared by `RoleService`). A new signed, append-only `AuditTrailReview` aggregate records audit trail reviews. Access review signing gets its own permission with a no-QA-yet fallback.

**Tech Stack:** .NET 10, EF Core 10, PostgreSQL, xUnit `[PostgresFact]`; React 19, TypeScript, MUI, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-11-qa-role-design.md`

## Global Constraints

- `CLAUDE.md` binds every task: separate DbContexts and `AsNoTracking` in tests, state + audit + negative cases, `[PostgresFact]` must run (Skipped > 0 is a failure), injected `TimeProvider`, `CancellationToken` forwarded, one explicit migration per schema change plus `dotnet ef migrations has-pending-model-changes`, no new `any`, `userEvent`, mock only `services/`.
- Role: `RoleType.Qa = 5`; name `"QA"`; display `"Quality Assurance"`; `IsSystemRole = true`.
- New permission codes exactly: `Audit.Review`, `Access.Review.Sign`. Both `IsEnforced = true`.
- New `SignatureMeaning` value appended at the end: `AuditTrailReviewed` (the enum is append-only; never renumber).
- QA forbidden codes = `SegregationOfDutiesRules.AdministrationCodes` ∪ (`GxpExecutionAndApprovalCodes` − {`Documents.Review`, `Documents.Approve`}) ∪ {`Sections.ConfigureAll`, `System.ConfigureSettings`, `MasterData.Manage`, `Items.Manage`, `Documents.ConfigManage`, `Kpi.ConfigureProfiles`, `Signatures.Manage`, `System.ManageJobs`}.
- `AuditTrailReview` and `AuditTrailReviewFinding` stay under automatic audit capture (no addition to `AuditCaptureExcludedTypes`).
- No existing user, role or grant is changed by the migration except adding the QA role and its grants.
- No change to sample review, approval, OOS or media release code.
- Reason / conclusion texts: 1–2000 characters. Finding note: 1–2000 characters.

## Review Focus

1. A custom role based on QA gains a laboratory permission through the permissions endpoint → `Custom_role_based_on_qa_refuses_forbidden_code` (Task 2).
2. Upgrade day with no QA user: nobody can sign an access review → `Administrator_can_sign_while_no_active_qa_signer_exists` and `Administrator_refused_once_active_qa_signer_exists` (Task 6).
3. Audit entries written after a review starts leak into its scope → `Scope_is_fixed_at_start_and_later_entries_are_excluded` (Task 4).
4. QA with `Sections.ViewAll` can write through an endpoint that only checks read scope → `Qa_is_refused_every_write_endpoint_group` (Task 3).
5. A signed review altered directly in the database → `Signed_review_update_and_delete_rejected_by_trigger` (Task 4) and the entry in `AppendOnlyTriggerCatalogPostgresTests.ProtectedTables`.

  - `Task<AuditTrailReviewDto> StartAsync(StartAuditTrailReviewRequest request, int actingUserId, CancellationToken ct = default)` — `request { Title, PeriodFromUtc, PeriodToUtc, ScopeKind, SectionId?, EntityName?, RecordId? }`; validates period (from < to ≤ now from `TimeProvider`); sets `CutoffAuditLogId = MAX(AuditLogs.Id)` and `EntryCount` = count in scope with `Id ≤ cutoff`.
  - `Task<PagedResult<AuditLogDto>> GetEntriesAsync(int reviewId, int page, int pageSize, CancellationToken ct = default)` — scope filters plus `Id ≤ CutoffAuditLogId`; page size clamped 1–100; reuses `AuditSearchService` filtering.
  - `Task<AuditTrailReviewFindingDto> AddFindingAsync(int reviewId, int auditLogId, string note, int actingUserId, CancellationToken ct = default)` — entry must be inside the fixed scope; review `InProgress`.

  - `Task<AuditTrailReviewFindingDto> CloseFindingAsync(int findingId, string comment, int actingUserId, CancellationToken ct = default)`.
  - `Task<IReadOnlyList<AuditTrailReviewListItemDto>> ListAsync(int page, int pageSize, CancellationToken ct = default)`, `Task<AuditTrailReviewDto> GetAsync(int id, CancellationToken ct = default)`; DTO carries `NewerEntriesCount` (entries in scope with `Id > cutoff`), signer full name, signed time, meaning text.
- Section scope kind: before coding, read how `AuditLog` rows can be tied to a section (columns available). If an audit row carries no section, drop `Section` from `AuditReviewScopeKind` and report it; do not approximate.
