# C6 Physicochemical

Scope: physicochemical instrument workspaces (HPLC, GC, ICP-OES), method masters, solution preparation and titrant standardization, working standards, reagents and reference standards, chromatography columns, equation types, physchem result panels, instrument report import. Facts only.

Labels: IMPLEMENTED = verified in code (cited). INTENDED = from spec (cited). DISCREPANCY = spec and code differ. REQUIRES CONFIRMATION = not determinable from code or spec read. The application was not run; screen behaviour is from code. Line numbers are from the files read; "not enumerated" = field list not read.

Abbreviations: SST = system suitability test; CCV = continuing calibration verification; ICV = initial calibration verification; LC = label claim; MC = moisture content; RS = reference standard; WS = working standard.

### WF-SOLN-002 Titrant standardization
- Start / trigger: on the record page of a Prepared titrant (code VS-...), the user presses "Standardize". Who: Solutions.Prepare, shown only for a titrant whose effective status is Prepared. [src: record/useTitrantStandardization.ts:L41-L45; SolutionPreparationController.cs:L92-L93]
- Prerequisites: the titrant solution master is configured for standardization (nominal strength and unit, standardization mode, replicate count, factor range, maximum RSD; blank and validity days as set): "This titrant is not configured for standardization." The preparation must not be expired or discarded ("This preparation is expired or discarded and cannot be standardized."). Mode PrimaryStandard needs the titrant's primary standard entry and equivalence, and a PrimaryStandard stock lot with purity and stock left; mode AgainstVolumetricSolution needs a reference titrant preparation of the configured reference solution that is itself Valid (or "restandardize before each use" and standardized today).
- Steps:
  1. User: presses "Standardize"; dialog "Standardize Titrant: {code or name}". System: loads standard lot options or reference options.
  2. User: enters one block per required replicate: Standard Lot and "Weight (mg)" (primary standard mode) or "Reference Solution" and "Ref Vol (mL)" (reference mode); "Titrant Vol (mL)"; "Blank (mL)" only if the titrant requires a blank; optional "Temperature (°C)" (-20 to 60; needed later for non-aqueous temperature correction).

System: validates the replicate count ("Exactly N replicate(s) are required.") and each replicate (BR-SOLN-010 messages), calculates the factor per replicate (BR-SOLN-011), evaluates against the factor range and maximum RSD, signs TitrantStandardized, deducts the standard weights from the lots (primary standard mode), and saves the record Passed or Failed with the failure reasons. - Final state: a signed standardization record; a Passed record sets the current factor and validity (standardization time + validity days, or "before each use" when validity is 0).
- Permissions per step: Solutions.Prepare for the write; reading by any authenticated user.
- Blocking conditions: unconfigured titrant, expired or discarded preparation, wrong or non-primary standard lot, lot without purity, insufficient stock, unacceptable reference standardization, volume not above the blank ("Replicate N: Titrant volume must be greater than the blank.").
- Signature points: one, TitrantStandardized.
- Use of the result: titration tests block or warn according to the factor state (WF-PHYSRESULT-002, BR-TITR-006).
- INTENDED source: docs/superpowers/specs/2026-09-29-hplc-chain-design.md section 4 (titrant standardization) and section 3.2 (titrant extras). ### WF-WS-001 Working standard qualification (create, assay, review, approve or reject)
- Start / trigger: a user opens Working Standards (/working-standards) and presses "New qualification" (initial) or "Requalify" on a lot. Who: WorkingStandards.Qualify to create or edit a draft and to upload documents; the page opens for any signed-in user. [src: WorkingStandardsController.cs:L48-L61; WorkingStandardsPage.tsx:L113-L149]
- Prerequisites: a reference-standard master entry for the material (Reagents and Reference Standards, MOD-REAGENT-001) that is active; for an initial qualification either a received raw-material sample with an approved assay result or a typed material name and batch, a quantity in grams and a storage location; a primary reference standard stock lot for the SST of the assay run; an HPLC method whose analyte uses that standard entry. For a requalification an existing working standard lot without an open qualification.
- Steps:
  1. Create (status Draft). User: dialog "New Working Standard Qualification" / "Requalify Working Standard": source "Manual" (Name, Batch) or "Received sample" ("Source Sample"), "Master Entry", "Quantity (g)", "Location", "Moisture %" (required for requalification), "Save". System: validates (BR-WS-003: "Choose the reference standard master entry." / "Master entry \"X\" is not a reference standard." / "That sample has no approved assay result." / "Enter the quantity in grams." / "Enter the storage location." / "Lot X already has an open qualification (CODE)." / "Moisture must be at least 0 and below 100 %."), creates the record WSQ-nn/MM/yyyy.
  2. Prepare the draft. User: moisture is entered in the create dialog ("Moisture %"); the server accepts later edits of a draft (UpdateDraft, "Only a draft qualification can be edited.") but no UI control for it was found in the drawer, which shows "Moisture Content" read-only (REQUIRES CONFIRMATION, GAP-619). For a typed source the user uploads the "Source Report" (and optionally a "Moisture Report") with "Upload" (PDF, PNG or JPEG). A new upload of the same kind supersedes the previous one.
  3. Assign to an HPLC run. User (Hplc.Operate and WorkingStandards.Qualify): in an open HPLC run whose SST Passed on a primary reference standard, presses "Assign Working Standard..." (a separate button beside "Assign Samples...") and selects the qualification in the list ("Assign Selected (N)"). System gates: "Sample assignment is locked until system suitability passes." / "A working standard can only be qualified against a primary reference standard - this run's system suitability used a working standard." / "Qualification X is already assigned to run Y." / "Qualification X is not eligible for this run." / "Enter the moisture content first." / "Attach the raw material's first test report first."
  4. Enter replicates. User: opens the qualification entry page, enters exactly 6 replicates (weight and one response of the qualified analyte), "Save Replicates". System: "Exactly 6 replicates are required (N entered)."; shows the preview (mean, RSD, potency, pass or fail).
  5. Upload the sample report and submit. User: uploads the sample report, presses "Send for Review" (dialog "Submit Qualification for Review", "Proceed to Sign"), Electronic Signature ("I confirm that chromatographic replicate data and evidence for working standard {code} ({material}) are complete, accurate, and ready for review."). System: gates "Upload the sample report before submitting." and "{analyte}: the system suitability standard values are incomplete."; calculates (BR-WS-002), signs ResultRecorded, stores the results; status Assayed, the submitter becomes "prepared by". A failed assay (Passed false) can only be rejected.
  6. Review. User (Samples.Review, not the submitter): "Review" (dialog "Review Qualification {code}", button "Sign & Review") signs Reviewed; status Reviewed. Alternatives: "Return to Draft" (reason, no signature; clears results and the submitter; replicates editable again even on a Completed run) or "Reject" (reason, signature; status Rejected). Gates: "Only an assayed qualification can be reviewed." / "A failed qualification can only be rejected." / "The analyst who submitted the qualification cannot review it." / "The run that carried this assay was abandoned - reject the qualification."
  7. Approve. User (Samples.Approve, neither the submitter nor the reviewer): "Approve" (dialog "Approve Qualification {code}", button "Sign & Approve") signs Approved; status Approved. Initial: creates the working standard lot (code WS-nn/MM/yyyy, unit g, purity = dried-basis potency, moisture, expiry = approval lab date + 12 months, location from the qualification). Requalification: updates the same lot's purity, moisture and expiry. Alternative: "Reject" at approval (reason, signature). Gates: "Only a reviewed qualification can be approved." / "The analyst who submitted the qualification cannot approve it." / "The reviewer cannot also approve the qualification." / "Another approval took that working standard code at the same moment - sign again."
  8. Use. The approved lot is listed with the status Valid, DueSoon (expires within 30 days), Expired or Depleted and can be chosen wherever a reference standard lot of that master entry is accepted (HPLC SST, relative titration); an expired lot is blocked by the common lot check.
- Review / approval: steps 6 and 7 are the review and approval, each with its own signature and segregation of duties (analyst, reviewer and approver must be three different people).
- Final state: Approved (lot created or extended) or Rejected; Draft after a return.
- Required vs optional data: required: master entry, source, quantity and location (initial), moisture before assigning, six replicates, sample report; optional: Moisture Report, comments, requalification note.
- Permissions per step: create, edit, upload: WorkingStandards.Qualify; assign, replicates, submit: Hplc.Operate and WorkingStandards.Qualify; review, return, reject at review: Samples.Review; approve, reject at approval: Samples.Approve. Default holders in roles. Analyst can create and submit but not review or approve; Reviewer can review but not create or approve; SectionHead holds all (with SoD limiting a person to one role per record).
- Signature points: submit (ResultRecorded), review (Reviewed), approve (Approved), reject (Rejected); return is not signed.
- Blocking conditions: SST not passed or used a working standard; moisture or source report missing; fewer or more than 6 replicates; RSD above 2.0 %; abandoned run; SoD.
- INTENDED source: docs/superpowers/specs/2026-10-03-working-standard-qualification-design.md (D1 to D12, sections 5 to 7, amendments 1 to 6). DISCREPANCY: spec D8 (no stock deduction at SST use) versus code (BR-WS-008, GAP-617). The spec names the approver "QC head" with Samples.Approve (GAP-614).
