## Phase 6 GMP / data-integrity facts

### MOD-SAMPLE-001 Sample receiving and register
- User accountability: electronically signed sample actions (correction, void, add laboratory) record the signer's user id, role, meaning and reason in the signature row. [BR-SAMPLE-006, -007, -009; verified-roles-permissions.md signatures]
- Receiving a sample is not signed. No explicit audit-log row was found in the receive code; automatic change capture on save is described only in the spec and was not verified. [audit-trail table; BusinessRules.md §11]
- Result modification: there is no endpoint to overwrite a stored count result in place. The only paths that change an entered result are Return to Analyst (C3), reviewer biochemical return, pathogen session reset, sample correction (batch/control number copied to result projection rows) and void. [TestWorkflowController/PathogenSessionController endpoint search; BR-SAMPLE-006]
- Controlled change of sample data: correction is signed, requires a reason, records old and new values per field, and is allowed only while the sample is Received or InTesting; afterwards the record is locked. [BR-SAMPLE-005/006]
- Item or location of a sample can change only before any test work exists; later the instruction is to void and receive again. [BR-SAMPLE-005]
- Void and correction of samples: void is signed, requires a reason, strikes the sample and its non-superseded tests, and writes an audit event with old/new status and the list of voided tests. There is no status precondition: an Approved or Rejected sample can be voided, and no check or notice concerns an already archived report (GAP-203). Voided is terminal. [BR-SAMPLE-007; SampleCorrectionService void path, verified]
- Role separation: `Samples.Correct` (Section Head, Reviewer, System Administrator by default) allows correction and void; nothing prevents the user who received or tested the sample from correcting or voiding it. [roles table; BR-SAMPLE-006/007]
- Analyst assignment is not signed; the reason is optional, and the audit log records previous and new names. Any active user of any role can be assigned. [BR-SAMPLE-008; GAP-213]
- Status control: sample status is a roll-up of laboratory section sign-offs; the least advanced open section decides. [BR-SAMPLE-011]
- Retest and new-sample spin-offs are created at approval (C3); in C2 the "Retest" cause of testing cannot be set or removed by correction. [BR-SAMPLE-005]
- EM, Water and After Cleaning receive and prepare endpoints require sign-in only; no permission code or lab-scope call. [GAP-227]

### MOD-PREP-001 Sample preparation
- Product / RM / PM preparation is signed (PreparationConfirmed); EM, After Cleaning and Water preparation is not signed. [BR-PREP-007, GAP-212]
- Preparation must be confirmed before incubation can start; a refused start is written to the audit log as TestStartRefused with a reason and to workflow history. [BR-PREP-004]
- The preparing user becomes the assigned analyst on all test orders created at EM/AC/Water preparation, and therefore counts as having performed those tests for the review and approval separation checks. [roles; BR-PREP-006]
- Item preparation configuration: saving or approving requires `Items.Manage`; no password or signature; approval records approver and time; any edit sets approval back to pending; analysts may use an unapproved configuration. The same user may save and approve (not checked). [BR-PREP-008..010]

### MOD-TESTING-001 / MOD-COUNT-001 / MOD-OBS-001 Testing
- Count, batch location and pathogen step results are not electronically signed; each row records the entering user and time. Qualitative physicochemical results are signed. [audit-trail table; GAP-218]
- Raw readings, dilution factor, configured dilution factor, override flag and justification note, average, calculated value, limit snapshot and status are stored with the reading. [BR-COUNT-003, BR-COUNT-011]
- Incubation rows record start time, media lot, incubator, user, stage and completion. [audit-trail table]
- Skip Wait records the overriding user and time on the incubation but takes no reason, no password and no signature. [BR-TESTING-007, GAP-226]
- Analyst-supplied incubation start times are accepted for selective plating and confirmatory setup. [GAP-224]
- Session reset (Section Head, `TestWorkflow.Supervise`) permanently deletes observations, step results, readings, results and incubations for the whole sample and writes one audit entry "ResetWorkflowSteps" with the reason; no password. Only Voided and Rejected samples are refused. [BR-PATH-012, GAP-221]
- Rework / retest at analyst level: the analyst cannot re-enter a stored count result; a retry of a non-definitive step uses "Retry This Step" before the order reaches Ready. After Ready, rework happens only through the reviewer's Return to Analyst (C3) or session reset. [WF-COUNT-001; BR-TESTING-014]
- Investigation: an Inconclusive confirmatory result is flagged "InconclusiveResult" with the history note "Confirmatory plating inconclusive - flagged for investigation."; no investigation record is created in C2. [BR-PATH-006]
- Segregation of duties: the review/approval checks treat the assigned analyst, the sample preparer and the author of any result, reading, observation, step result, analysis or confirmatory observation as having "performed" the test; the check is role-agnostic. [roles; SegregationOfDutiesGuard]
- The screens Primary Matrix, Shared TSB panel and Session Review contain wording that refers to "ALCOA+" ("... saved successfully with ALCOA+ contemporaneous tracking!", "Audit & Traceability (ALCOA+ Compliance)", "... per ALCOA+ contemporaneous recording requirements"). These are UI strings; no validation evidence exists in the repository for them. [PrimaryObservationMatrixPanel.tsx:453; SessionReviewPanel.tsx:561; BrothStepPanel.tsx:350, grep verified]
- Session security: see C1 (not reviewed here).

## Guide callouts
1. Receiving, correcting, voiding and assigning samples have no approved intended-workflow document; the guide must describe screen behaviour only. (GAP-200..203, GAP-213)
2. A sample can be voided at any status except already Voided, including after approval or rejection. (GAP-203)
3. Count, batch location and pathogen results are not electronically signed at entry; qualitative physicochemical results are. (GAP-216, GAP-218)
4. Sample preparation for EM, Water and After Cleaning is not signed and has no ownership check; the preparer becomes the assigned analyst. (GAP-212, GAP-227)
5. Skip Wait bypasses minimum incubation time with no reason, password or signature. (GAP-226)
6. The single-stage count result has no server-side time check; the screen gates it only on the client. (GAP-202)
7. The pathogen session reset permanently deletes all entered data for the sample. (GAP-221)
8. Pathogen session completion needs no password and moves the whole sample to review. (GAP-222)
9. Client and server disagree on confirmatory agreement when media show No Growth and Non-Conforming growth. (GAP-223)
10. The EM out-of-trend rule in the specification is not implemented. (GAP-211)
11. The register shows "Cancelled / Voided" for three different statuses. (GAP-204)
12. Item preparation configuration approval has no located screen and no segregation check. (GAP-214, BR-PREP-010)
13. Any active user can be assigned as analyst regardless of role or laboratory. (GAP-213)
14. EM, Water and After Cleaning receive and prepare endpoints require sign-in only. (GAP-227)
15. Several screens display the wording "ALCOA+"; the guide must not repeat it as a compliance statement. (new item, no existing GAP)
16. No Final Release step exists in the application; testing ends at review/approval (R3). (GAP-017, GAP-018)
