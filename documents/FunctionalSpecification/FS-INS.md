## Scope and reading notes

- This document covers `HplcWorkspaceController` and `IcpWorkspaceController`, `HplcRunService` (and its partial files), `IcpRunService` (and its partial files), the sample entry contexts, the two submission recorders (`HplcMethodAssayRecorder`, `IcpMethodAssayRecorder`), the calculation helpers named in each entry, and the report readers in `InstrumentImport/`. Working standard qualification on an HPLC run (`AssignQualifications`, `SubmitQualification`) is in FS-WST. The dissolution calculation that uses an HPLC run's standard is in FS-PHY-006. The cleaning-residue calculation (`CleaningResidueCalculator`) is in FS-ACL. The HPLC and ICP method masters, the column master and the instrument agent ingest (`InstrumentIngestService`) were not read for this document.
- Every statement was written from the code files named in each entry. Nothing was run. Pharmacopoeia chapters are pointers only (to be confirmed by QA).
- Criteria for system suitability, theoretical weights, standard dilutions, injection counts, impurity correction factors, the reference solution percent and the disregard limit are configured by the Section Head in the method master and are copied into the run when it starts. The replicate count for a sample comes from the stage replicate configuration of the test (`StageReplicateResolver`). Specification limits are configured by the Section Head.
- Two ICP rules are written in the code and not configured: the minimum correlation 0.999 and the calibration validity of 24 hours (`IcpDefaults`). See CONF-097.
- Every run service method calls `EnsureAccessAsync`. A run outside the user's scope is reported as "not found" (NotFoundException), not as unauthorised. Read access uses the readable sections (all sections for `Sections.ViewAll`); write access uses the user's member sections for every role.
- Both run entities and all their child rows are audited by the context's automatic capture; none is in `AuditCaptureExcludedTypes`. Every table also has an automatic `xmin` concurrency token. None of the methods in this document calls `RecordVersion.EnsureCurrent`; there is no stale-form version check, although the run detail returned to the screen carries a `Version`.
- Methods that sign (SST confirmation, ICP calibration confirmation, ICP sample assignment, sample submission) call `IElectronicSignatureService.SignAsync` before any other change is made, so a wrong password leaves the data unchanged (the signature service records its own failed-attempt audit row; see FS-SIG).
- Rounding in this document is `MidpointRounding.AwayFromZero` wherever "rounded" is written. Values are `decimal`.

## Functions

### FS-INS-001
**Satisfies:** URS-INS-001
**Function:** Permissions of the two workspace controllers. Both controllers need only a signed-in user for the read actions (instruments, method options, run history, run detail, eligible tests, sample entry, test order evidence, report values, evidence file download); the services then check section scope. Every write action (start run, save and confirm SST or calibration, abandon, complete, assign and remove samples, save replicates or entry, submit, upload and supersede evidence) needs the permission `Hplc.Operate`. The actions for working standard qualifications additionally need `WorkingStandards.Qualify`. Section scope: `EnsureAccessAsync` reads `GetSectionIdsAsync(userId, access)`; for write access this is the user's member sections even for a user who holds `Sections.ViewAll`; a run whose section is not in scope is reported as not found. `StartRunAsync` checks that the equipment's section is in the user's member sections and otherwise reports the equipment as not found. `GetInstrumentsAsync` and `GetMethodOptionsAsync` list only equipment and methods in the readable sections. `GetRunHistoryAsync` reports equipment outside the readable sections as not found. The submit actions call `ITestWorkflowEngine.SubmitHplcMethodAssayAsync` and `SubmitIcpMethodAssayAsync`, which check write scope of the test order again (FS-INS-009, FS-INS-014). No action reads an `If-Match` header. No action checks that the caller is the analyst who started the run: any user with `Hplc.Operate` in the section may change an open run.
**Code:** `backend/MicroLIMS.API/Controllers/HplcWorkspaceController.cs` — class `HplcWorkspaceController`; `backend/MicroLIMS.API/Controllers/IcpWorkspaceController.cs` — class `IcpWorkspaceController`; `backend/MicroLIMS.Application/Services/HplcRunService.cs` — `EnsureAccessAsync`; `backend/MicroLIMS.Application/Services/IcpRunService.cs` — `EnsureAccessAsync`
**Verified by:** reading (not run)

### FS-INS-002
**Satisfies:** URS-INS-002, URS-INS-003
**Function:** Instrument state and starting an HPLC or GC run. The instrument list shows each piece of equipment of the technique (type Gc for GC, otherwise Hplc) as Running (an open run exists), Unavailable with a reason, or Available. An instrument is Unavailable when its calibration due date is before the laboratory-local date ("Calibration overdue since ..."), or when an equipment inventory row with the same code (compared in upper case) has the status OutOfService or Retired. `StartRunAsync` (inputs: equipment, method, column, one prepared mobile phase per channel) refuses in this order: equipment not found or outside the member sections; an open run already on the equipment; the unavailable reasons above; method not found; the equipment type not matching the method's technique; the method inactive; the method belonging to another laboratory than the equipment; column not found, inactive, or not on the compatible equipment list of the column; column with no USP designation, or a designation that differs (without regard to letter case) from the method's column designation; a number of mobile phases other than the method's channel count; for each method channel, a missing selection, a preparation that is not of type MobilePhase, not of the channel's solution master, not prepared for this method, or whose effective status (from the injected clock) is not Prepared. The preparation's release status (approval status) is not checked here, only the effective status Prepared (CONF-101). The column's own expiry or qualification status is not checked in this method. The method is saved as a JSON copy in the run (all later checks read this copy, not the live method). A run code and an SST code are generated (`SystemSuitabilityRunCode.NextAsync`, method abbreviation and laboratory-local date), the run is set Open with the analyst and start time from the injected clock, and an SST record in status Pending is created with one row per method analyte. The calibration due date is checked at start only (CONF-096). The equipment inventory check matches by the equipment code, and a code with no inventory row passes.
**Code:** `backend/MicroLIMS.Application/Services/HplcRunService.cs` — `GetInstrumentsAsync`, `DetermineUnavailableReasonAsync`, `StartRunAsync`
**Verified by:** reading (not run)
**Conflicts:** CONF-096, CONF-101

### FS-INS-003
**Satisfies:** URS-INS-004, URS-INS-005
**Function:** Save system suitability entries (`PUT runs/{id}/sst`). The run must be open and the SST record Pending. For each analyte row: the row must belong to this SST record and to a method analyte; for an assay method the standard weight must be above zero (residual-solvent and related-substances methods do not weigh the standard); the standard lot must exist, belong to the run's section and pass `LotUsability.Check` against the method analyte's configured standard entry (linked to that reagent, not awaiting release, not rejected, not expired by laboratory-local date, stock above zero); for an assay method the lot must have a recorded purity and moisture. The row stores the lot, the weight and the lot's purity and moisture copied at that moment, and the entered resolution, tailing factor, theoretical plates, retention factor, signal-to-noise, peak-to-valley and reported RSD. The injections are replaced by the entered responses. If the method has an internal standard, an internal standard response above zero is required for every injection and the effective response is response divided by internal standard response; if it has none, internal standard responses are refused. While entering, the mean of the effective responses and the RSD (sample standard deviation, n minus 1, divided by the mean, times 100; empty with fewer than 2 injections; 0 when the mean is 0) are stored for display. The entered responses are not checked for sign or count at save time; that is done at confirmation.
**Code:** `backend/MicroLIMS.Application/Services/HplcRunService.cs` — `SaveSstAsync`; `backend/MicroLIMS.Application/Helpers/LotUsability.cs` — `Check`; `backend/MicroLIMS.Application/Helpers/StandardComparisonCalculator.cs` — `CalculatePreparationRsd`; `backend/MicroLIMS.Application/Helpers/HplcResponse.cs` — `ForSst`
**Verified by:** reading (not run)

### FS-INS-004
**Satisfies:** URS-INS-004, URS-INS-005
**Function:** Confirm system suitability (`POST runs/{id}/sst/confirm`; inputs: password and comment). Preconditions: run open; SST Pending; every required entry present (`MissingSstEntries`: reference standard lot; standard weight above zero for assay methods; a response above zero for each of the method's standard injections; the internal standard response for each injection when the method has one; each of resolution, tailing factor, theoretical plates, retention factor, signal-to-noise and peak-to-valley that the method has a criterion for); a current standard report evidence file of the SST context; and every mobile phase preparation still has the effective status Prepared. The server then evaluates each analyte with `HplcSstEvaluator.Evaluate` using the criteria saved in the run's method copy: a failure is recorded when the number of injections differs from the method's standard injection count; when any injection response is not above zero; when the RSD (as in FS-INS-003) is above the method's maximum RSD (strictly above; skipped with fewer than 2 injections); when a resolution, retention factor, theoretical plates, signal-to-noise or peak-to-valley value is below its minimum, or the tailing factor is above its maximum (equal to the limit passes); and when a value is missing for a criterion that is set. The SST is Passed only when every analyte has no failure. Stock deductions are planned before signing: the weights of the analytes that share one lot are summed, converted from mg to the lot's unit (grams: divided by 1000; kilograms: divided by 1,000,000; any other unit is refused), and the lot is checked again by `LotUsability.Check` with that quantity (so a lot with less stock than needed is refused). After a successful signature (meaning SuitabilityRunPerformed, bound to the SST record) the method stores the mean response, RSD, pass flag and reasons for each analyte, reduces the lot quantities in the same save, sets the SST status to Passed or Failed, the combined reasons, the confirming user, the time from the injected clock and the signature. A failed SST is confirmed and signed in the same way and the standard is deducted either way. A Failed SST is final for the run (the status is no longer Pending, so entries cannot be changed and samples cannot be assigned). The criteria values come from the method master; none is written in the code.
**Code:** `backend/MicroLIMS.Application/Services/HplcRunService.cs` — `ConfirmSstAsync`, `PlanSstStockDeductionsAsync`, `MissingSstEntries`; `backend/MicroLIMS.Application/Helpers/HplcSstEvaluator.cs` — `Evaluate`
**Verified by:** reading (not run)

### FS-INS-005
**Satisfies:** URS-INS-006, URS-INS-016
**Function:** Eligible tests, assignment, removal, completion and abandoning of an HPLC or GC run. `GetEligibleTestsAsync` (read access; optional search over sample number, batch, item name and test code) lists test orders whose test definition has the workflow type HplcMethodAssay or Dissolution with the run's method, that belong to the run's section, are not superseded, are not at Ready, Reviewed or Approved, whose sample is not Voided or Cancelled, that are not assigned to another run that is not abandoned, and that have no active `TestAnalysis`. `AssignSamplesAsync` (write scope) needs the run open and the SST Passed ("locked until system suitability passes"), at least one test, and every chosen test order to be in the eligible list (otherwise it names the other run or says not eligible). For dissolution tests the run's method copy must be an assay method with no internal standard, exactly one analyte and a standard dilution above zero. No signature is asked for assignment in the HPLC workspace (the ICP workspace asks for one; see FS-INS-013). `RemoveSampleAsync` needs a reason (trimmed, at most 500 characters), a run that is open, a sample still assigned, and (for a test order) no active `TestAnalysis`; the sample is marked Removed with reason, time and user and is kept. `CompleteRunAsync` needs the run open and refuses when any assigned sample (or draft working standard qualification) has not been sent for review; for dissolution an order counts as sent when it has an active result and has already reached a finished step. It sets Completed and the closing time. `AbandonRunAsync` needs a run that is open and a reason (trimmed, at most 500 characters), and sets Abandoned with the reason and time; samples on an abandoned run no longer block their test orders.
**Code:** `backend/MicroLIMS.Application/Services/HplcRunService.Samples.cs` — `GetEligibleTestsAsync`, `EligibleOrdersQuery`, `AssignSamplesAsync`, `RemoveSampleAsync`, `CompleteRunAsync`, `SubmittedOrderIdsAsync`; `backend/MicroLIMS.Application/Services/HplcRunService.cs` — `AbandonRunAsync`
**Verified by:** reading (not run)

### FS-INS-006
**Satisfies:** URS-INS-007
**Function:** Replicate entry for an HPLC or GC sample (`PUT samples/{runSampleId}/replicates`). The run sample is loaded with its order, the run's method copy, the SST and the specifications (`HplcSampleEntryContext.LoadAsync`). The entry is refused unless it is editable: the run sample is still assigned, no result has been sent for review (an active `TestAnalysis`), and the run is Open, or Completed with the result returned to the analyst. Dissolution orders are refused ("entered on the Testing page"). The replicates are validated: if the method has an internal standard each replicate needs an internal standard response above zero, otherwise a response is refused; a sample weight above zero is required, except that related-substances and cleaning-residue replicates accept zero and refuse a negative weight; peaks are accepted for related-substances methods only (at most 50 per replicate, area not negative and not above 1,000,000,000,000, an impurity that belongs to the method, relative retention above 0 and at most 100); each replicate needs exactly one response per method analyte, and no response of an analyte outside the method; the response must be above zero for assay, zero or more for residual solvents and cleaning residue, zero or more for related substances (where it is the reference solution's principal-peak area). All previous replicates are removed and the new ones saved in one transaction (replace-all). The required number of replicates comes from the stage replicate configuration; at submission `EntryProblem` refuses a different count ("Expected exactly N replicates"), or no replicate when no count is configured. Entry also requires, at preview and submission, that the SST has Passed, that an after-cleaning sample uses a cleaning-residue method, that the specification for each analyte exists on the item, and that the SST standard values are complete; a dried or anhydrous basis needs the sample's moisture result (FS-PHY-014).
**Code:** `backend/MicroLIMS.Application/Services/HplcRunService.Samples.cs` — `SaveReplicatesAsync`, `ValidatePeaks`, `ReplaceReplicatesAsync`; `backend/MicroLIMS.Application/Services/HplcSampleEntryContext.cs` — `LoadAsync`, `EditableProblem`, `EntryProblem`, `SubmitProblem`
**Verified by:** reading (not run)

### FS-INS-007
**Satisfies:** URS-INS-008
**Function:** HPLC assay calculation, as coded. For each analyte and replicate the assay percent is `StandardComparisonCalculator.CalculatePreparationAssay`: the sample response divided by the SST mean response, times the actual standard weight divided by the method's theoretical standard weight, times the method's theoretical test weight divided by the actual sample weight, times (100 minus the standard's moisture percent) divided by 100, times the standard's purity percent. All of these inputs must be above zero (moisture from 0 to below 100). The response is the effective response (divided by the internal standard response when the method has one). The method's theoretical weights, the SST mean, the standard weight, purity and moisture come from the method copy and the confirmed SST. The result is the mean of the replicate assay percents. A dried or anhydrous basis (from the specification's result basis) multiplies the mean by 100 divided by (100 minus the sample's moisture percent) and rounds that result to 2 decimals; otherwise the mean is not rounded. The status is `SpecificationEvaluator.Evaluate` of the specification on that value (rule in FS-MIC-007), made on the value before display rounding. The displayed text rounds to 1 decimal followed by " %" (CONF-095). When the stage role of the sample is Bulk the calculation is individual: each replicate is judged separately against the specification and gets its own row. When the stage role is Finished and the item has an amount-per-unit specification with a label claim, a second row is added: amount per unit = mean assay percent times label claim divided by 100, shown to 2 decimals with the label claim unit and judged unrounded. Which stage role applies, and the dried or anhydrous basis, come from the item's configuration. The calculation takes no account of a blank titre (the optional blank parameter of `CalculatePreparationAssay` is not passed by any caller found in `backend/MicroLIMS.Application`).
**Code:** `backend/MicroLIMS.Application/Helpers/HplcAssayCalculator.cs` — `Calculate`, `ApplyBasis`, `AmountPerUnit`, `IsIndividualBasis`, `JudgesAmountPerUnit`; `backend/MicroLIMS.Application/Helpers/StandardComparisonCalculator.cs` — `CalculatePreparationAssay`; `backend/MicroLIMS.Application/Helpers/HplcSampleAssayEvaluator.cs` — `Evaluate`, `FormatPercent`
**Verified by:** reading (not run)
**Conflicts:** CONF-095

### FS-INS-008
**Satisfies:** URS-INS-009
**Function:** GC residual solvent and HPLC related substance calculations. Residual solvents: for each replicate, ppm = standard concentration (µg/mL) times sample solution volume (mL) divided by (sample weight in mg divided by 1000), times (replicate response divided by the SST mean response); the weight and the standard values must be above zero and the response zero or more. The result is the mean of the replicate ppm values, shown rounded to 1 decimal followed by " ppm" and judged by `SpecificationEvaluator.Evaluate` on the unrounded mean. When every replicate response is zero the display is "Not detected" and the value is 0. The standard concentration and solution volume come from the method copy. Related substances: per replicate each peak's percent = peak area times the impurity's correction factor (1 when the peak is not a method impurity) divided by the replicate's reference solution area, times the method's reference solution percent. A peak counts unless its area is zero or, when a disregard limit above zero is configured, its percent is below that limit. The rows are the specifications' related-substance rows: Named (the percents of the peaks of that impurity, summed; zero when below the disregard limit), UnspecifiedEach (the highest counted percent among the peaks that are not named by a specification, per replicate), TotalOthers (the sum of the counted percents of those peaks) and Total (named impurities that pass the disregard limit plus the other counted peaks). The row value is the mean over replicates. With no signal the display is "Not detected" and the value 0; with a disregard limit, a mean below the limit gives "< limit %" and value 0, otherwise the mean rounded to 2 decimals; without a disregard limit a mean that rounds to 0.00 or is 0 gives "< 0.01 %". The status is `SpecificationEvaluator.Evaluate` on the stored value, which for a value below the disregard limit or 0.01 is 0 (the compared value is the one after this rounding). The reference solution percent, the disregard limit, correction factors and relative retentions come from the method master. The code comment states a ruling that UnspecifiedEach takes the per-replicate maximum and then the mean.
**Code:** `backend/MicroLIMS.Application/Helpers/ResidualSolventCalculator.cs` — `Calculate`, `FormatPpm`; `backend/MicroLIMS.Application/Helpers/HplcResidualSolventEvaluator.cs` — `Evaluate`; `backend/MicroLIMS.Application/Helpers/RelatedSubstancesEvaluator.cs` — `Calculate`
**Verified by:** reading (not run)
**Conflicts:** CONF-095

### FS-INS-009
**Satisfies:** URS-INS-010
**Function:** Send an HPLC or GC sample result for review (`POST samples/{runSampleId}/submit`; inputs: password, comment). `HplcMethodAssayRecorder.SubmitCoreAsync` runs in one transaction: it loads the entry context, checks write scope of the test order, and refuses when `SubmitProblem` gives a reason (entry not editable, SST not passed, replicate count or content wrong, specification or SST standard values missing, moisture missing, or no current sample report evidence file for this run sample, "Upload the sample report before sending for review"). It then runs the shared checks of FS-PHY-002 with the workflow type HplcMethodAssay and no equipment ID, so the equipment checks of FS-PHY-002 are skipped; the analysis time is the injected clock time, not an entered value. For an assay with a dried or anhydrous basis it reads the sample's own moisture result with the row lock of `ResolveLockedAsync` (FS-PHY-014). It builds the rows by the calculations of FS-INS-007 and FS-INS-008 (or FS-ACL for cleaning residue) and stores one parameter result per row, with a calculation text that holds the inputs, the replicates, the run and SST codes and the method ID, then signs and saves as FS-PHY-002 (signature meaning ResultRecorded; analysis equipment = the run's instrument; validity record = the SST record). The status of each row is the status the preview showed. No check is made at submission that the instrument's calibration is still in date, that the column is still in service, or that the mobile phase preparations are still within expiry; those were checked at run start or SST confirmation (CONF-096). Replicates are stored as readings of kind Replicate.
**Code:** `backend/MicroLIMS.Application/Workflows/TestWorkflow/HplcMethodAssayRecorder.cs` — `SubmitCoreAsync`; `backend/MicroLIMS.Application/Workflows/TestWorkflow/TestWorkflowSupport.cs` — `ValidateTestAnalysisOrderAsync`, `PersistTestAnalysisAndFinalizeAsync`
**Verified by:** reading (not run)
**Conflicts:** CONF-096

### FS-INS-011
**Satisfies:** URS-INS-012
**Function:** Start, save and confirm an ICP calibration. `IcpRunService.StartRunAsync` checks that the equipment exists and is in the user's member sections (otherwise not found), is of type IcpOes, has no open run, and is not unavailable (calibration due date before the laboratory-local date, or inventory status OutOfService or Retired; as in FS-INS-002). It creates the run Open and a calibration record Pending with generated codes. `SaveCalibrationAsync` needs the run open and the calibration Pending. The calibration standard, if given, must be a lot of type ReferenceStandard of the run's section that passes `LotUsability.Check` (against its own master entry). Each element has a symbol (normalised, no duplicates) and a correlation r typed by the analyst, between 0 and 1, rounded to 6 decimals. The server judges each element with `IcpCalibrationEvaluator`: r missing fails; r below 0.999 fails; r equal to or above 0.999 passes (`IcpDefaults.MinCorrelation`, written in the code, CONF-097). The r value is entered by the analyst; the server does not calculate it from a curve, and the calibration report file is not read. `ConfirmCalibrationAsync` needs the run open, the calibration Pending, a standard lot, at least one element, a current calibration report evidence file, and at least one element that passes. It checks the standard lot again, signs (meaning SuitabilityRunPerformed, bound to the calibration), judges the elements again, and sets Confirmed with the user, the time from the injected clock and the signature. A confirmed calibration is usable for 24 hours from the confirmation time (`IcpDefaults.CalibrationValidHours`, written in the code, CONF-097). Unlike the HPLC SST, confirming an ICP calibration does not deduct any stock from the standard lot.
**Code:** `backend/MicroLIMS.Application/Services/IcpRunService.cs` — `StartRunAsync`, `DetermineUnavailableReasonAsync`; `backend/MicroLIMS.Application/Services/IcpRunService.Calibration.cs` — `SaveCalibrationAsync`, `ConfirmCalibrationAsync`, `ConfirmBlockReason`, `RequireStandardLotAsync`; `backend/MicroLIMS.Application/Helpers/IcpCalibrationEvaluator.cs` — `Evaluate`; `backend/MicroLIMS.Application/Helpers/IcpDefaults.cs` — `MinCorrelation`, `CalibrationValidHours`
**Verified by:** reading (not run)
**Conflicts:** CONF-096, CONF-097

### FS-INS-012
**Satisfies:** URS-INS-013, URS-INS-016
**Function:** ICP sample assignment, removal, entry and completion. `AssignBlockReason` refuses when the run is not open, the calibration is not Confirmed, the calibration has expired (24 hours after confirmation, injected clock), or no element passed. `GetEligibleTestsAsync` lists test orders with the workflow type IcpMethodAssay in the run's section, not superseded, not finalised, whose sample is not Voided or Cancelled, not on another non-abandoned run and without an active `TestAnalysis`. `AssignSamplesAsync` (write scope) refuses a test order that is not eligible and signs once for the whole action (meaning SampleAssignedToRun, bound to the run; password required) before adding the samples with that signature. `RemoveSampleAsync` needs a reason and a run that is Open or Completed (so a returned sample on a completed run can be removed), a sample still assigned and no active `TestAnalysis`. `SaveEntryAsync` (write scope) needs the entry to be editable (as in FS-INS-006) and the calibration to be confirmed and in date; the test must have at least one needed element (the elements that the item's specifications refer to); an actual weight in grams above zero is required for assay tests that are not after-cleaning and refused otherwise; exactly one concentration (ppm) per needed element is required, for needed elements only, and none may be negative. The existing concentration rows are updated or added. `CompleteRunAsync` needs the run open and every assigned sample to have an active `TestAnalysis`. `AbandonRunAsync` needs a reason (trimmed, at most 500 characters). For an after-cleaning sample with no item, the specifications are built from the test's elements that have a cleaning limit in ppm (not more than that limit).

### FS-INS-013
**Satisfies:** URS-INS-013, URS-INS-014
**Function:** ICP element availability and result calculation. `IcpElementAvailability.Evaluate` decides, for each element the test needs: not valid when the calibration is not confirmed, when it has expired, when the element was not calibrated on this run (symbols compared without regard to letter case), or when it failed calibration. `IcpSampleEvaluator.Evaluate` builds a row for each specification of the test, in display order. A specification whose element is not valid, or has no entered concentration, gives a row with a problem text and no value. The result is a ppm value when the specification unit is "ppm" or the test mode is Impurity: the value is the entered concentration itself (0 means not detected). Otherwise it is an assay percent: result ppm times the test's theoretical amount times (specific gravity for a Liquid sample form, otherwise 1) times 100, divided by (the element's target ppm times the actual weight in grams); target, theoretical amount and specific gravity must be above zero where used, and the actual weight must be above zero. The target ppm, theoretical amount, sample form and specific gravity come from the test master. The status is `SpecificationEvaluator.Evaluate` on the unrounded value. The display rounds an assay to 1 decimal followed by " %" and a ppm value to 4 decimals followed by " ppm" (CONF-095).
**Code:** `backend/MicroLIMS.Application/Helpers/IcpSampleEvaluator.cs` — `Evaluate`; `backend/MicroLIMS.Application/Helpers/IcpContentCalculator.cs` — `AssayPercent`; `backend/MicroLIMS.Application/Services/IcpElementAvailability.cs` — `Evaluate`, `ExpiresAt`
**Verified by:** reading (not run)
**Conflicts:** CONF-095, CONF-097

### FS-INS-014
**Satisfies:** URS-INS-010, URS-INS-013
**Function:** Send an ICP sample result for review (`POST samples/{runSampleId}/submit`; inputs: password, comment). `IcpMethodAssayRecorder.SubmitCoreAsync` runs in one transaction. It loads the entry context, checks write scope of the test order, and refuses when `SubmitProblem` gives a reason: the entry is not editable; the calibration is not confirmed or has expired; a specification is not linked to an element of the test; no needed element; the actual weight is missing for an assay; a concentration is missing; any needed element is not valid on this run; any row has a problem; or there is no current sample report evidence file for this run sample. It then runs the shared checks of FS-PHY-002 with the workflow type IcpMethodAssay and no equipment ID (so the equipment checks of FS-PHY-002 are skipped), the analysis time being the injected clock time. One parameter result is stored per row with the status computed in FS-INS-013 and a calculation text that holds the element, the concentration, the weights, the run and calibration codes, the confirmation time and the analyst-entered r. ### FS-INS-015
**Satisfies:** URS-INS-015
**Function:** ICP report values (`GET samples/{runSampleId}/report-values`). Read access to the run is checked. The method refuses if no report reader is configured. It needs a current sample report evidence file for the run sample, reads its text with `IReportTextReader` (a PDF text layer, or optical character recognition; the reader is registered with Tesseract), parses it with `IcpReportParser` (solutions, each with a Sample ID label, readings per element with wavelength, value and unit; bracketed values are standards and an unlabelled or empty solution is a blank), and returns the candidate sample solutions. A solution is proposed automatically only when exactly one solution labelled with the sample's reference number has a reading for every needed element, or no such solution is complete and exactly one labelled solution exists; otherwise the analyst must choose and a message says so. For each needed element it returns the reading, wavelength, and a note when the unit is not mg/L or the printed value is negative. The response states the text source (text layer or OCR) and whether verification is required. The method writes nothing: values are saved only when the analyst saves the entry (FS-INS-012) with the same checks. `EmpowerReportParser` (an HPLC Empower report reader that extracts fields and peaks and flags OCR values that two OCR passes read differently) is in the same folder; no call to it was found in the application code outside tests, so it has no function in the current system.

### FS-INS-016
**Satisfies:** URS-INS-011
**Function:** Evidence files of an ICP run. The rules are those of FS-INS-010 with these differences: the allowed kind depends on the context (Calibration: CalibrationReport only; Sample: SampleReport or Other; any other context: Other only); a Sample file needs a run sample that is on the run and not removed; a file linked to a sample is refused for other contexts; the upload is read in blocks and refused when larger than 25 MB; the stored path is `icp-evidence/{run}/{id}{extension}`. Supersede needs a reason, an open run, evidence not already superseded, and a sample that is not removed. The reviewer view lists the current sample evidence of the order and the current calibration report of each run the order was on, after read access to the test order is checked.
