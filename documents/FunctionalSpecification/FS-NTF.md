## Scope and reading notes

- This document covers `DashboardController`, `DashboardLabScopeService`, `DashboardNotificationService`, `MyTasksService` (the task list only), `Dashboard/SectionHeadQueueBuilder`, `MessageController`, `MessageService`, `MyWorkController`, `MyWorkService`, `MyWorkUrgency`, the `IMyWorkSource` implementations, `TestSelfAssignmentController`, `TestSelfAssignmentService`, `TestReleaseRules`, and the frontend My Work module (`frontend/src/modules/myWork/*` and `Sidebar.tsx`). `DashboardService` (the figures, the Section Head and reviewer dashboards, today's work, the incubation overview) and `RecentActivityService` are called by `DashboardController` but were not read; their rules are not described here.
- Every statement was written from the code files named in each entry.
- Audit. `NotificationLog` is on the audit exclusion list (`AuditCaptureExcludedTypes`: derived reminders and read state, not a GxP record), so notification rows are not audited. The conversation, participant and message entities are not on that list, so their saves are audited by the automatic capture. Dashboards, notifications and the My Work read endpoints make no regulated decision. Taking and releasing a test order in `TestSelfAssignmentService` write explicit `AuditLog` rows (`TEST_TAKEN` and `TEST_RELEASED`) in the same transaction as the `TestOrder.AssignedAnalystId` update.
- Concurrency. None of the dashboard or message methods in this document calls `RecordVersion.EnsureCurrent` (no stale-form version check). `TestSelfAssignmentService.TakeAsync` and `ReleaseAsync` save under the `TestOrder` PostgreSQL `xmin` concurrency token and catch `DbUpdateConcurrencyException`.

## Functions

### FS-NTF-001
**Satisfies:** URS-NTF-001
**Function:** Dashboard access and laboratory scope. The controller is `[Authorize]`; the user ID is read from the name-identifier claim and the role from the role claim (parsed as the `RoleType` enum). Endpoints take an optional `lab` code. `DashboardLabScopeService.ResolveAsync` first gets the user's readable sections (null for `Sections.ViewAll`). With no `lab` the scope is those sections. With a `lab`: an unknown code is refused with a business-rule error (`LaboratoryCodes.IsKnown`); the code is upper-cased and mapped to the active sections with that code; for a user with a section list, the result is the overlap and an empty overlap is refused with `UnauthorizedAccessException` ("not a member of this laboratory"); for a user with `Sections.ViewAll` the scope is all sections of that laboratory. The known laboratory codes are "MICRO" and "FP". The endpoints `section-head` and `reviewer` need the policies `Dashboards.LabOverview` and `Dashboards.Review`. The endpoints `my-tasks` and `analyst-metrics` return 403 (`Forbid`) unless the role claim is Analyst; this test is on the role, not on a permission. The other endpoints (summary, kpi-deltas, monthly-trend, category-distribution, status-distribution, recent-activity, todays-work, incubation-overview, notifications) need only a signed-in user. The `notifications` endpoint without `lab` returns every notification of the user. The services that compute the figures were not read.
**Code:** `backend/MicroLIMS.API/Controllers/DashboardController.cs` — class and actions; `backend/MicroLIMS.Application/Services/DashboardLabScopeService.cs` — `ResolveAsync`

### FS-NTF-002
**Satisfies:** URS-NTF-002
**Function:** Notifications. `GetNotificationsAsync(role, userId)` computes the current notifications, stores new ones, pushes them, and returns the user's 30 newest stored notifications (so a read request writes rows). A recompute-throttle may be present; when it says the user is not due, the call returns the stored list only, and a new notification can appear up to one window late. The computed notifications, limited to the user's readable sections where the record has a section: (1) MediaExpiry: media with status Active and expiry date up to now plus 7 days; severity "error" when the expiry is not after now, else "warning"; (2) IncubationReady: incubations with a completion time set, whose test order is in the section scope, is on the Incubating or Running step, is not superseded and has status Pending or InProgress; the 20 newest by completion time; severity "info"; (3) ApprovalWaiting: for the role SectionHead, or a user who holds `Dashboards.LabOverview`, a count of samples with a section sign-off under approval; and PendingPreparationConfigApproval, a count of item preparation configurations pending review (no section filter); (4) ReviewWaiting: for the roles Reviewer or SectionHead, or a holder of `Dashboards.Review`, a count of samples with a section sign-off under review; (5) TestReturnedForRevision: tests assigned to the user that were returned in the last 12 hours, severity "warning", with the reason text; (6) monitoring reminders from `MonitoringReminderService`, when that service is present. Storing: a notification whose message text equals a message stored for the same user in the last 12 hours is skipped. For each new one a `NotificationLog` row is added and a push is sent; for severity "error" the row is marked as emailed and an email is sent to the address `{username}@microlims.local`. The pushes and emails are sent before the single `SaveChangesAsync` of the batch. With a `lab`, the list is then filtered: a notification with a test order is kept if the order's section is in the laboratory's sections; the types MediaExpiry, IncubationReady, PendingPreparationConfigApproval and TestReturnedForBiochemical are kept only for Microbiology; a notification with only a sample is kept if the sample has a test in those sections; the rest are kept. `MarkAsReadAsync` marks one of the user's own notifications read and returns silently when it is not found or not the user's. `MarkAllAsReadAsync` marks all of the user's unread notifications read by a direct update. The 7-day window and the 12-hour window are written in the code. The approval and review waiting rules differ from the text of `BusinessRules.md` section 12.
**Code:** `backend/MicroLIMS.Application/Services/DashboardNotificationService.cs` — `GetNotificationsAsync`, `ComputeAsync`, `PersistAndDeliverAsync`, `MarkAsReadAsync`, `MarkAllAsReadAsync`

### FS-NTF-003
**Satisfies:** URS-NTF-003
**Function:** Analyst task list (`GET api/dashboard/my-tasks`, analysts only, see FS-NTF-001). Test orders assigned to the user (`AssignedAnalystId`), not superseded and not Approved, Rejected, Voided or Cancelled, limited to the user's sections (or the chosen laboratory's). A test order with a pending return gives a "Revise Test" task with urgency Overdue and the return reason. Otherwise the earliest open incubation (completion time empty, expected reading time set) gives a "Read Test" task when its expected reading time is no later than now plus 2 days; the 2-day and the 4-hour windows are written in the code. Urgency: Overdue if the due time is before now; DueSoon if within 4 hours; DueToday if on the same date; else DueTomorrow. Media evaluations not completed, for lots prepared by the user (restricted to the laboratory's sections when a laboratory is chosen), give a task for the earliest open challenge incubation due within the same window. The list is sorted by due time. This "ready to read" rule (an open incubation due within two days) is not the rule of the IncubationReady notification (a completed incubation), see FS-NTF-002. The method writes nothing.

### FS-NTF-004
**Satisfies:** URS-NTF-004
**Function:** Messages (`api/messages`, any signed-in user). Create conversation: an initial message is required; the creator is added to the participants; there must be at least two distinct participants; any inactive user among them refuses the request; for a one-to-one conversation that already exists between the two users, the message is added to it instead; otherwise the conversation, participants, first message and the creator's read mark are saved, and the other active participants are notified (a `NotificationLog` row of type "DirectMessage" with the first 80 characters of the text, and a push, through `NotifyMessageSentAsync`; a failure there is logged and swallowed, so the message is still saved). Send message: content must not be blank; the sender must be a participant, else `UnauthorizedAccessException`; the message and the new last-message time are saved with the UTC time from the injected clock, and the participants are notified. Read messages: the user must be a participant; `take` is clamped to 1 to 100; deleted messages are left out; newest are taken, then returned oldest first. Get conversation by ID: refused unless the user is a participant. Mark read: sets the user's last-read message to the newest undeleted message; does nothing if the user is not a participant. Unread count is computed per conversation as messages with a higher ID than the last read, sent by others, not deleted. The create and send methods run in one transaction. No role, permission or laboratory-scope check applies to who may be added to a conversation. There is no endpoint to edit or delete a message. Conversation and message rows are saved with the automatic audit capture.
**Code:** `backend/MicroLIMS.Application/Services/MessageService.cs` — `CreateConversationAsync`, `SendMessageAsync`, `GetMessagesAsync`, `GetConversationByIdAsync`, `MarkAsReadAsync`, `GetTotalUnreadCountAsync`; `backend/MicroLIMS.API/Controllers/MessageController.cs` — actions

### FS-NTF-005
**Satisfies:** URS-NTF-005
**Function:** Section Head queue builder (pure functions; the data is loaded elsewhere, by `DashboardService`, which was not read). Review queue: one row per (sample, section) under review; submitted time from the section sign-off, else a stored clock start, else the sample's received time; age in hours rounded to 1 decimal (`Math.Round`, default midpoint rule); analyst names from the assigned analyst of each test, else the latest result entry; the worst result level of the entry's tests; ordered by age, oldest first. Approval queue: one row per (sample, section) under approval; reviewed time and reviewer name; same age rule. Attention items: overdue tests (the reason text says the testing stage was pending for the delay in hours, "(>168h / 7-day Analyst SLA)"; the selection of overdue orders is made by the caller; at most 5 samples); retests in progress (reason "Retest sample in progress" with the origin reference; urgency High); delayed reviews and delayed approvals (entries with an age of 24 hours or more; at most 5 each; urgency Medium). The 168-hour, 24-hour and 5-item numbers are written in the code. The display name of a sample is the item name, else the water point code, department, machine, else the reference.

### FS-NTF-006
**Satisfies:** URS-NTF-006, URS-NTF-008
**Function:** My Work aggregator and endpoints (`GET api/my-work` with optional query `lab`, and `GET api/my-work/summary`; `MyWorkController` is `[Authorize]`). The caller's user ID is read from the `ClaimTypes.NameIdentifier` claim (never a route or query parameter). When `lab` is provided on `GET api/my-work`, `DashboardLabScopeService.ResolveAsync` validates the laboratory code (`MICRO` or `FP`) and resolves the caller's section scope for that laboratory. `MyWorkService.BuildContextAsync` builds `MyWorkContext` once per request with the caller's active role permission codes, `ReadableSectionIds` (`IUserSectionScopeService.GetReadableSectionIdsAsync`, or `lab.SectionIds` when a laboratory is chosen), `MemberSectionIds` (`GetMemberSectionIdsAsync`, intersected with `lab.SectionIds` when a laboratory is chosen), `NowUtc` from `ILabClock.UtcNow`, `EndOfLabDayUtc` (the next local midnight in `ILabClock.LabTimeZone`, advanced past any invalid daylight-saving transition hours and converted to UTC), and the system settings `myWork.lookAheadDays` (`SystemSettingKeys.MyWorkLookAheadDays`, integer, default `7`, range `1` to `30`) and `myWork.readOverdueHours` (`SystemSettingKeys.MyWorkReadOverdueHours`, integer, default `0`, range `0` to `168`). `MyWorkService.GetAsync` runs each registered `IMyWorkSource` where `AppliesTo(ctx)` is true sequentially on the request `DbContext`, requesting up to `GroupCap` (`50`) items per source. Items are merged into eleven fixed groups in display order: `readyToRead` ("Ready to read now"), `returned` ("Returned to me"), `endingToday` ("Incubation ending today"), `toPerform` ("Tests to perform"), `review` ("Awaiting my review"), `approval` ("Awaiting my approval"), `available` ("Available in my section"), `unassigned` ("Unassigned tests"), `documents` ("Documents"), `equipment` ("Equipment"), and `materials` ("Media, solutions and strains"). Empty groups (`Count == 0 && LockedCount == 0`) are omitted. Within each group, items are ordered by `Locked` (`false` before `true`), then `Urgency` (`Overdue = 0`, `Now = 1`, `Today = 2`, `Later = 3`, `None = 4`), then `SortAtUtc` ascending, and truncated to 50 items (`HasMore` is true when `Count + LockedCount > shown.Count`). `Count` holds the exact unlocked total; `LockedCount` holds the locked total. If an applicable source throws any exception other than `OperationCanceledException`, its `Key` is appended to `UnavailableSources` and the error is recorded via `IErrorCaptureService.CaptureAsync` while the remaining sources still return. `MyWorkService.GetSummaryAsync` runs `CountAsync` on each applicable source with no laboratory filter; when all applicable sources succeed it returns `MyWorkSummary(total, overdue, now, Complete: true)`, and when any source throws it captures the error and returns `MyWorkSummary(null, null, null, Complete: false)`.
**Code:** `backend/MicroLIMS.API/Controllers/MyWorkController.cs` — `Get`, `GetSummary`; `backend/MicroLIMS.Application/Services/MyWork/MyWorkService.cs` — `GetAsync`, `GetSummaryAsync`, `BuildContextAsync`, `EndOfLabDayUtc`; `backend/MicroLIMS.Application/Services/MyWork/IMyWorkSource.cs`; `backend/MicroLIMS.Application/Services/MyWork/MyWorkContext.cs`; `backend/MicroLIMS.Application/DTOs/MyWorkDtos.cs`; `backend/MicroLIMS.Application/Services/SystemSettings/SystemSettingDefinitions.cs` — `All` (`myWork.lookAheadDays`, `myWork.readOverdueHours`)
**Verified by:** `MyWorkServiceTests`, `MyWorkEndpointsPostgresTests`

### FS-NTF-007
**Satisfies:** URS-NTF-007, URS-NTF-008
**Function:** Server-clock urgency rules and analyst, document, equipment, and material sources. `MyWorkUrgency` computes urgency from the injected clock times in `MyWorkContext`: (1) `ForDueDate(dueAtUtc, nowUtc, endOfLabDayUtc)` returns `None` when `dueAtUtc` is null, `Overdue` when `due < nowUtc`, `Today` when `due <= endOfLabDayUtc`, and `Later` when `due > endOfLabDayUtc`; (2) `ForReading(ready, readySinceUtc, expectedUtc, nowUtc, endOfLabDayUtc, readOverdueHours)` returns `Overdue` when `ready` is true, `readOverdueHours > 0`, and `nowUtc - readySinceUtc > TimeSpan.FromHours(readOverdueHours)`, otherwise `Now` when `ready` is true; when `ready` is false, it returns `None` if `expectedUtc` is null, `Today` if `expectedUtc <= endOfLabDayUtc`, and `Later` otherwise; (3) `ForStatusAge(enteredStatusAtUtc, nowUtc)` returns `Overdue` when `nowUtc - enteredStatusAtUtc > SampleWorkflowQueues.OverdueAfter` (24 hours) and `None` otherwise. One ready-to-read rule (`SampleWorkflowQueues.IsIncubationReadyToRead` and SQL predicate `IsIncubationReadyAt`) is shared by My Work, `MyTasksService.GetMyTasksAsync`, and the workspaces: an open incubation on an active test (`!IsSuperseded`, status `Pending` or `InProgress`) is ready when `ExpectedReadingAt <= now`, `IncubationEndUtc <= now`, or `MinimumDurationOverriddenByUserId != null`. Sources that apply to all signed-in users (`AppliesTo` returns true): (a) `IncubationSource` (`Key = "incubations"`): open incubations on active tests in `ReadableSectionIds` where `TestOrder.AssignedAnalystId == userId` or `Incubation.StartedByUserId == userId`, excluding tests with a pending return for the user; ready incubations go to `readyToRead` (target `incubation-read`, action `read`), and non-ready incubations with `(ExpectedReadingAt ?? IncubationEndUtc) <= EndOfLabDayUtc` go to `endingToday` (target `incubation-read`, urgency `Today`); (b) `ReturnedTestsSource` (`Key = "returnedTests"`): latest `TestReturnEvent` on an active test in `ReadableSectionIds` where both `TestReturnEvent.AssignedAnalystId` and `TestOrder.AssignedAnalystId` equal `userId` and no active `CountTestReading` exists (`AnalystQueries.MyPendingReturns`), placed in `returned` with urgency `Now`, return reason in `Context`, and target `test-step`; (c) `AssignedTestsSource` (`Key = "assignedTests"`): active tests in `ReadableSectionIds` with `AssignedAnalystId == userId`, no open incubation, and no pending return, placed in `toPerform` with urgency from `ForStatusAge(Sample.ReceivedAt, nowUtc)`, target `test-step`, and action `release` when `TestReleaseRules.ReleasableAsync` holds; (d) `MaterialsSource` (`Key = "materials"`): in `ReadableSectionIds`, concatenates incomplete `MediaEvaluations` on media lots prepared by `userId` (`Due` = earliest open challenge incubation `ExpectedReadingAt`, target `media-evaluation`), `Media` lots in status `Prepared` or `Active` prepared by `userId` with `ExpiryDate <= nowUtc + LookAheadDays` (target `media`), `SolutionPreparations` in status `Prepared` prepared by `userId` with `ExpiresAt <= nowUtc + LookAheadDays` (target `solution`), and `ThawEvents` thawed by `userId` with `DestructionItem == null` and `ThawedAt <= nowUtc - CryovialThaw.DestructionReminderAfter` (`Due` = `ThawedAt + DestructionReminderAfter`, target `cryovial`); (e) `DocumentsSource` (`Key = "documents"`): across sections, concatenates `DocumentReviewTasks` assigned to `userId` in status `Pending` or `InProgress` (target `document-review`), `DocumentApprovalTasks` assigned to `userId` in status `Pending` (target `document-approval`), and `DocumentTrainingAssignments` assigned to `userId` in status `Assigned`, `Reading`, `Overdue`, `KafPending`, or `Failed` (target `training-assignment`). `EquipmentSource` (`Key = "equipment"`) applies only when `ctx.Permissions` contains `EquipmentWork.Record` (`PermissionConstants.EquipmentWorkRecord`), returning open non-retired `EquipmentTasks` (`CompletedOn == null && RetiredByRevisionId == null`) with `DueDate <= labToday.AddDays(ctx.LookAheadDays)` (target `equipment-task`, due timestamp at `23:59:59` local date in the laboratory time zone), without filtering by owner or laboratory section.
**Code:** `backend/MicroLIMS.Application/Services/MyWork/MyWorkUrgency.cs` — `ForDueDate`, `ForReading`, `ForStatusAge`; `backend/MicroLIMS.Application/Services/SampleWorkflowQueues.cs` — `IsIncubationReadyToRead`, `IsIncubationReadyAt`, `IsOpenIncubationOnActiveTest`; `backend/MicroLIMS.Application/Services/MyTasksService.cs` — `GetMyTasksAsync`; `backend/MicroLIMS.Application/Services/MyWork/Sources/AnalystQueries.cs`; `backend/MicroLIMS.Application/Services/MyWork/Sources/IncubationSource.cs`; `backend/MicroLIMS.Application/Services/MyWork/Sources/ReturnedTestsSource.cs`; `backend/MicroLIMS.Application/Services/MyWork/Sources/AssignedTestsSource.cs`; `backend/MicroLIMS.Application/Services/MyWork/Sources/MaterialsSource.cs`; `backend/MicroLIMS.Application/Services/MyWork/Sources/DocumentsSource.cs`; `backend/MicroLIMS.Application/Services/MyWork/Sources/EquipmentSource.cs`

### FS-NTF-008
**Satisfies:** URS-NTF-008
**Function:** Review and approval sources with Segregation of Duties locking (`ReviewSource`, `ApprovalSource`, `SignoffQueueSource`, `SegregationOfDutiesGuard`). `ReviewSource` (`Key = "review"`) applies when the caller holds `Samples.Review` (`PermissionConstants.SamplesReview`) and loads `SectionReviewQueues.Candidates` and `Entries` for `SectionSignoffStatus.UnderReview` in the caller's `MemberSectionIds` (`Sections.ViewAll` does not widen review or approval queues). Each `(Sample, SectionId)` entry is timed from `SampleSectionSignoff.SubmittedForReviewAt` (falling back to `SampleWorkflowQueues.GetReviewClockStartsAsync`, then `Sample.ReceivedAt`), given urgency from `MyWorkUrgency.ForStatusAge`, and assigned target `sample-review` and action `review` when unlocked. `ApprovalSource` (`Key = "approval"`) applies when the caller holds `Samples.Approve` (`PermissionConstants.SamplesApprove`) or `Media.Release` (`PermissionConstants.MediaRelease`). With `Samples.Approve`, it loads `SectionSignoffStatus.UnderApproval` entries in `MemberSectionIds`, timed from `SampleSectionSignoff.ReviewedAt` (or `SampleWorkflowQueues.GetApprovalClockStart`), with target `sample-approval` and action `approve` when unlocked. With `Media.Release`, it also queries `Media` rows in `MemberSectionIds` with `ApprovalStatus == ApprovalGateStatus.PendingReview` and at least one completed `Conform` `MediaEvaluation`, timed from the latest completed evaluation timestamp (or `PreparedAt`), with target `media-approval` and action `approve` when unlocked. Segregation of Duties locking is evaluated in batch via `SegregationOfDutiesGuard.GetTestOrderIdsPerformedByAsync(userId, testOrderIds)` (one query per table across all candidate test orders, checking `TestOrders.AssignedAnalystId`, `SamplePreparations.PreparedByUserId`, `Results.EnteredByUserId`, `CountTestReadings.EnteredByUserId`, `PathogenObservations.ObservedByUserId`, `WorkflowStepResults.SubmittedByUserId`, `TestAnalyses.EnteredByUserId`, and `ConfirmatoryPlateObservations.RecordedByUserId`; `DidUserPerformTestAsync` delegates to this batch method). If any test order in the sample section was performed by the caller, the entry is marked `Locked = true` with `LockReason = "You performed a test on this sample"`. In `ApprovalQueue`, if not already locked for performance and `(signoff?.ReviewedByUserId ?? sample.ReviewedByUserId) == userId`, the entry is marked `Locked = true` with `LockReason = "You reviewed this sample"`. For media release items, if `Media.PreparedByUserId == userId` or any `MediaEvaluationChallenge` on the lot has `ReadByUserId == userId`, the item is marked `Locked = true` with `LockReason = "You prepared or evaluated this media lot"`. Locked items carry an empty `Actions` list, sort after unlocked items, and are counted only in `LockedCount` (excluded from `Count` and `CountAsync`).

### FS-NTF-009
**Satisfies:** URS-NTF-009
**Function:** Test self-assignment (take and release) and unassigned test sources (`TestSelfAssignmentController`, `TestSelfAssignmentService`, `TestReleaseRules`, `AvailableTestsSource`, `UnassignedTestsSource`). Migration `AddTestsSelfAssignPermission` seeds the permission `Tests.SelfAssign` (`PermissionConstants.TestsSelfAssign`) and grants it to the Analyst role. Both `POST api/testorders/{id:int}/take` and `POST api/testorders/{id:int}/release` require `[Authorize(Policy = PermissionConstants.TestsSelfAssign)]` and resolve the acting user ID from `ClaimTypes.NameIdentifier`. `TestSelfAssignmentService.TakeAsync(testOrderId, userId)` checks in order: (1) the caller is an active user whose role holds `Tests.SelfAssign` (otherwise throws `UnauthorizedAccessException`); (2) system setting `workflow.selfAssignment.enabled` (`SystemSettingKeys.SelfAssignmentEnabled`, boolean, default `"true"`) is true (otherwise throws `BusinessRuleException("Taking tests is switched off. Ask a Section Head to assign this test.")`); (3) the test order exists and its `SectionId` is within the caller's readable sections (otherwise `NotFoundException` or `UnauthorizedAccessException`); (4) `order.AssignedAnalystId` is null (otherwise throws `BusinessRuleException("Already taken by {full name}.")`); (5) the test is not superseded, `OutsourcedToLab` is null, and `Status` is `Pending` or `InProgress` (otherwise throws `BusinessRuleException("This test is closed, replaced or outsourced and can no longer be taken.")`); and (6) `AnalystAssignmentRules.EnsureAssignableAsync` passes with `assigneeId == actingUserId` (active, unlocked user with role `Analyst`, `Reviewer`, or `SectionHead`, and member of `order.SectionId`). It adds an `AuditLog` row via `SampleAssignmentService.BuildAssignmentAudit` with action `TEST_TAKEN`, old value `"{TestCode}: Unassigned"`, new value `"{TestCode}: {FullName}"`, sets `order.AssignedAnalystId = userId`, and saves in one transaction under the `TestOrder` `xmin` concurrency token; on `DbUpdateConcurrencyException`, the assignment and audit row roll back and the method reloads the current holder to throw `"Already taken by {full name}."` (or `"This test was changed by someone else. Refresh and try again."`). `TestSelfAssignmentService.ReleaseAsync(testOrderId, userId)` verifies `Tests.SelfAssign`, loads the test order, requires `order.AssignedAnalystId == userId` (otherwise `"Only the analyst who holds this test can release it."`), and checks `TestReleaseRules.ReleasableAsync`. `TestReleaseRules.ReleasableAsync` requires all three conditions: (a) the test is assigned to `userId`, has `OutsourcedToLab == null`, is not superseded, and has status `Pending` or `InProgress`; (b) the latest `AuditLogs` row for `EntityName == "TestOrder"` and `EntityId == testOrderId` whose `Action` is in `{"AssignedAnalyst", "UnassignedAnalyst", "ReassignedAnalyst", "TEST_TAKEN", "TEST_RELEASED"}` has `Action == "TEST_TAKEN"` and `UserId == userId` (so a test assigned or reassigned by a Section Head cannot be released); and (c) `userId` has recorded nothing on the sample across `Results` (`EnteredByUserId`), `CountTestReadings` (`EnteredByUserId`), `PathogenObservations` (`ObservedByUserId`), `WorkflowStepResults` (`SubmittedByUserId`), `TestAnalyses` (`EnteredByUserId`), `Incubations` (`StartedByUserId` or `CompletedByUserId`) on any test order of the sample, and `SamplePreparations` (`PreparedByUserId`) on the sample. If not releasable, `ReleaseAsync` throws `BusinessRuleException("This test can no longer be released. Ask a Section Head to reassign it.")`. When releasable, it adds an `AuditLog` row with action `TEST_RELEASED` (old value `"{TestCode}: {FullName}"`, new value `"{TestCode}: Unassigned"`), sets `order.AssignedAnalystId = null`, and saves under `xmin` concurrency. In My Work, `AvailableTestsSource` (`Key = "availableTests"`, group `available`) applies when the caller holds `Tests.SelfAssign` and returns unassigned open non-outsourced tests in `MemberSectionIds` with target `test-step` and action `take` while `workflow.selfAssignment.enabled` is true (empty when false). `UnassignedTestsSource` (`Key = "unassignedTests"`, group `unassigned`) applies when the caller holds `Samples.AssignAnalyst` (`PermissionConstants.SamplesAssignAnalyst`), returning unassigned open non-outsourced tests in `ReadableSectionIds` with target `sample-assign` and action `assign` regardless of `workflow.selfAssignment.enabled`.
