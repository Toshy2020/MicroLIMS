## Scope and reading notes

- This document covers the physicochemical endpoints of `TestWorkflowController` (measurement, gravimetric, qualitative, dissolution, disintegration, weight variation, titration, UV spectrophotometry, outsourcing), the testing workspace (`TestingWorkspaceController`) and the results read endpoint (`ResultController`). The microbiology endpoints of the same controller are in FS-MIC and FS-PAT. HPLC and ICP method assays (`HplcMethodAssayRecorder`, `IcpMethodAssayRecorder`) are in FS-INS. Titrant standardisation and solution preparation are in FS-SOL.
- Every statement was written from the code files named in each entry. Nothing was run. Pharmacopoeia chapters are pointers only (to be confirmed by QA).
- Limits, replicate counts, equations, unit counts, stage offsets and band percentages are configured by the Section Head in the Test Master and the item Specifications. Some of these have a number written in the code that is used when the configured value is empty. Where that is so, the entry says so and quotes the number as it is in the code. See CONF-093.
- Rounding in this document is `Math.Round(..., MidpointRounding.AwayFromZero)` wherever "rounded" is written. Values are `decimal`.
- Recording uses an automatic audit of every changed row (`MicroLimsDbContext.SaveChangesAsync`). None of the entities written here is in `AuditCaptureExcludedTypes`. Every entity table also carries an automatic `xmin` concurrency token, so two overlapping saves of the same row are refused. None of the methods in this document calls `RecordVersion.EnsureCurrent`; there is no stale-form version check.
- The shared checks and the common save are described once, in FS-PHY-002. Each result type then refers to it.
- No method in this document checks the physicochemical area (finished product, or raw and packaging material) of the user when a result is recorded. See CONF-094.

## Functions

### FS-PHY-001
**Satisfies:** URS-PHY-001
**Function:** Permission and section scope for the physicochemical recording endpoints. `TestWorkflowController` needs the permission `TestWorkflowExecute` on every action. The record endpoints `record-measurement-result`, `record-gravimetric-result`, `record-titration-result`, `record-uv-result`, `record-qualitative-result`, `record-dissolution-result`, `record-dissolution-stage`, `record-disintegration-result`, `record-disintegration-stage`, `record-weight-variation-result` and `record-weight-variation-stage` call `IUserSectionScopeService.EnsureTestOrderAccessAsync` with write access before the engine is called. Write access is always the user's own member sections, for every role, including a user who holds `Sections.ViewAll`. The method refuses with UnauthorizedAccessException when the test order belongs to a section the user is not a member of, and returns without error when the test order does not exist. The engine then checks scope again (FS-PHY-002), and the stage methods check it as well. `GET titration-context` checks read access inside `TitrationContextService.GetContextAsync`. `GET moisture` calls `EnsureTestOrderAccessAsync` for the test order with the default access, which is write access (member sections only, so a user who holds `Sections.ViewAll` but is not a member is refused), and then the same write-access check for the moisture test order (FS-PHY-014). `outsource` needs the permission `TestsOutsource` instead, and `record-outsourced-result` needs `TestWorkflowExecute`; neither controller action calls the scope check itself, and the scope check is made inside the engine (FS-PHY-013). A `WorkflowStepException` is returned as HTTP 400 with the error code as the first error. Any other business rule failure is raised as an exception and is not caught in the controller. No endpoint here checks that the caller is the analyst assigned to the test order (`AssignedAnalystId`). No endpoint here checks the physicochemical area (finished product, raw and packaging) of the user. None of these endpoints reads an `If-Match` header.
**Code:** `backend/MicroLIMS.API/Controllers/TestWorkflowController.cs` — `RecordMeasurementResult`, `RecordGravimetricResult`, `RecordQualitativeResult`, `RecordDissolutionResult`, `RecordDissolutionStage`, `RecordDisintegrationResult`, `RecordDisintegrationStage`, `RecordWeightVariationResult`, `RecordWeightVariationStage`, `RecordTitrationResult`, `RecordUvResult`, `Outsource`, `RecordOutsourcedResult`, `RunAsync`

### FS-PHY-002
**Satisfies:** URS-PHY-001, URS-PHY-002, URS-PHY-011, URS-PHY-013
**Function:** The shared checks and the shared save used by every result type in this document except the stage methods. `ValidateTestAnalysisOrderAsync` runs these checks in this order. (1) The password must not be blank. (2) At least one parameter result must be supplied, except for dissolution, disintegration, weight variation, HPLC method assay and ICP method assay. (3) The analysis time is made UTC (an unspecified kind is taken as UTC) and is refused when it is later than the injected clock plus 5 minutes. No lower bound is checked, so an analysis time before the sample was received is not refused. (4) The test order must exist, must not be at Ready, Reviewed or Approved (`RequireOrderNotFinalized`), and must not be superseded. (5) An outsourced test order is refused by every ordinary recorder, and the outsourced recorder refuses a test order that was not outsourced. (6) The test definition is found by the test code and its workflow type must equal the type the recorder expects. (7) Write-scope access to the test order is checked. (8) Only one active `TestAnalysis` may exist per test order; a second is refused. (9) If equipment is given, it must exist; if an equipment inventory row with the same code exists, its status must be InService; and the equipment's section code must be the text "FP" (compared without regard to letter case), which is the code of the Physicochemical Laboratory section. No calibration or qualification status of the equipment is checked here, and no calibration due date is read. If no inventory row has the equipment's code, the status check is skipped. (10) The sample must be linked to an item, except that an After Cleaning sample is allowed through for HPLC and ICP method assays. (11) The specifications are those of the item, the test code, the applicable grade and the applicable production stage (`SpecificationLookup.ApplicableGradeAsync`, `ApplicableStageAsync`); none found is an error. (12) For dissolution, disintegration and weight variation exactly one specification must exist and have the limit type DissolutionQ, DisintegrationTime or WeightVariation. For other types the supplied specification IDs must be the specification IDs of the test, each exactly once. `PersistTestAnalysisAndFinalizeAsync` then: signs with `IElectronicSignatureService.SignAsync` using the user ID from the sign-in claims, the entered password and the meaning ResultRecorded, bound to entity "TestOrder" and the test order ID (the signature service verifies the password; see FS-SIG); adds a `TestAnalysis` row with the entering user, the entered-at time from the injected clock, the equipment, the conditions text, the comment and the signature; adds the parameter results; computes the overall status (OutOfSpecification if any parameter is, else RequiresReview if any is, else WithinLimits if any is, else the first parameter's status); adds a `Result` row (raw value text, interpreted value text, type Numeric or Interpretive); saves; projects each parameter result to the reporting table (`ResultProjectionService`); moves the test order to Ready through `WorkflowStateMachine.TransitionAsync` (which writes a `WorkflowHistory` row); calls `SampleReviewService.AutoSubmitForReviewIfReadyAsync` (FS-REV-003); and saves again. Each result method runs inside one transaction (`UnitOfWork.RunAsync`). Every changed row is audited by the context's automatic capture; the signature is a separate row. The signature meaning, signer name and time are not shown by this method; display of them is in FS-SIG and FS-RPT.

### FS-PHY-003
**Satisfies:** URS-PHY-003, URS-PHY-013
**Function:** Record a measurement result (`record-measurement-result`). Inputs: analysis time, equipment ID, comment, password and, for every specification of the test, a list of readings. After FS-PHY-002 the method requires that the test definition has a replicate count from 1 to 30 and an evaluation basis, and that each parameter has exactly the replicate count of readings. Calculation as coded, per parameter: n is the number of readings; the mean is the sum divided by n; the minimum and maximum are taken; when n is 2 or more the standard deviation is the square root (Newton iteration, rounded to 10 decimals) of the sum of squared differences from the mean divided by n minus 1, and when the mean is not zero the relative standard deviation is the standard deviation divided by the mean times 100, rounded to 10 decimals. The reported value and the value compared with the specification depend on the evaluation basis from the test definition: Mean uses the mean, Min the lowest reading, Max the highest reading, and EachValue reports the mean but marks the result OutOfSpecification if any one reading is out of specification (otherwise the first status other than WithinLimits that a reading gives, RequiresReview taking precedence over a limits-not-configured status). The comparison is made by `SpecificationEvaluator.Evaluate` on the unrounded value (rule in FS-MIC-007). The reported text rounds the reported value to a number of decimals equal to the largest number of decimals found in the readings as typed and in the specification's target, tolerance, lower limit and upper limit (trailing storage zeros of the limits removed), and appends the specification unit. The standard deviation and relative standard deviation are stored in the calculation text and are not compared with any limit. The canonical limit text is the specification's limit text, or one built from its fields. The full readings are stored as replicate readings. The specification's limit type must be numeric or a count-tiered type, otherwise `SpecificationEvaluator` refuses. The reading values are not checked for sign or range in this method.

### FS-PHY-004
**Satisfies:** URS-PHY-003
**Function:** Record a gravimetric result (`record-gravimetric-result`). After FS-PHY-002 the test definition must have the equation type GravimetricLoss or GravimetricResidue and a replicate count from 1 to 30, and each parameter must have exactly that many replicates. Whether a container (tare) weight is used comes from the test definition: a container weight is required for every replicate if it is used, and refused if it is not. The condition fields are the comma-separated labels configured on the test definition; if labels are configured, the request must carry exactly those labels, each with a non-blank value, and no other; if none are configured, no condition may be sent. The conditions are stored as text on the analysis. Calculation as coded, per replicate: W1 is the initial weight minus the container weight (zero when none), W2 the final weight minus the container weight. W1 must be above zero, W2 must not be negative, and W2 must not be above W1; otherwise the method refuses. For GravimetricLoss the percent is (W1 minus W2) times 100 divided by W1. For GravimetricResidue the percent is W2 times 100 divided by W1. The reported value is the mean of the replicate percents, compared with the specification unrounded (FS-MIC-007). The reported text rounds to the larger of 2 decimals and the number of decimals of the specification target, tolerance, lower limit and upper limit, and appends the specification unit, or the percent sign when the specification has no unit. The container, initial and final weights and the computed percent of each replicate are stored as weight readings.

### FS-PHY-005
**Satisfies:** URS-PHY-004

### FS-PHY-006
**Satisfies:** URS-PHY-005
**Function:** Record the first stage of a dissolution test (`record-dissolution-result`). Before FS-PHY-002 the method refuses a medium volume at or below zero, a dilution factor given and at or below zero, a vessel area count other than 6, and any vessel area at or below zero. After FS-PHY-002 (which requires exactly one DissolutionQ specification) the condition fields are checked as in FS-PHY-004. The standard comes from `HplcDissolutionStandard.ResolveAsync`: the HPLC run sample that is assigned to this test order and whose run is not abandoned (the newest one); the run's system suitability must be Passed; the saved method must be an assay method with exactly one analyte, no internal standard and a standard dilution above zero; the system suitability record must have a mean response above zero, a standard weight above zero, a purity above zero and a moisture value. Otherwise the method refuses with the reason. Values read from the specification are Q = the lower limit and the label claim; neither is checked before use, so a specification without them stops with a server error rather than a rule message. Calculation as coded: Cs is the standard weight times (purity divided by 100) times ((100 minus moisture) divided by 100) divided by the standard dilution (each input must be above zero, moisture from 0 to below 100). Each vessel percent is vessel area times Cs times medium volume times dilution factor times 100, divided by (standard mean area times label claim), all inputs above zero; the dilution factor is 1.0 when none is given. The stage offsets come from the test definition and are 5, 15, 25 and 2 (stage 1 offset, stage 2 minimum offset, stage 3 minimum offset, stage 3 maximum count below the stage 2 minimum) when the test definition has none (CONF-093). Stage rule: for 6 vessels, Complies if every vessel is at or above Q plus the stage 1 offset, otherwise NextStageRequired. The reported value is the mean of all vessel percents, shown rounded to 0 decimals followed by " %". Q must be above 0 and not above 100, and the offsets may not be negative. Each vessel also gets a pass flag against its own stage threshold (stage 1: Q plus the stage 1 offset; stage 2: Q minus the stage 2 minimum offset; stage 3: Q minus the stage 3 minimum offset). The full standard values, volume, dilution factor, label claim, Q and offsets are stored in the calculation text. The analysis is saved with its signature. If the outcome is NextStageRequired the method stops there: no `Result` row is added, the test order does not move to Ready, and the status NextStageRequired is returned. Otherwise the `Result` row, projection, move to Ready and automatic submission are done as in FS-PHY-002. The code comment cites a USP <711> reading and a laboratory decision of 2026-09-19 (chapter pointer only, to be confirmed by QA).

### FS-PHY-007
**Satisfies:** URS-PHY-005
**Function:** Record a later dissolution stage (`record-dissolution-stage`). The password must not be blank and at least one vessel area is required, each above zero. The test order must exist, not be finalised or superseded, and be a Dissolution test; write scope is checked. The active analysis must exist and its active parameter result must have the status NextStageRequired. If 6 readings exist the request must carry exactly 6 areas (stage 2, 12 vessels in all); if 12 exist it must carry exactly 12 (stage 3, 24 in all); any other count is refused. The earlier stages are not recalculated from the current specification: the standard, medium volume, dilution factor, label claim, Q and offsets are read from the calculation text saved at stage 1, and the new vessels are evaluated together with the earlier ones by the same rules as FS-PHY-006. The new vessel readings are added. The earlier values remain only in the audit trail (the automatic capture records old and new values of the changed rows). It does not check that the user is different from, or the same as, the user who recorded the earlier stage, and it does not check equipment, conditions or the specification again. If the outcome is still NextStageRequired the method stops; otherwise a `Result` row is added and the test order moves to Ready as in FS-PHY-002.

### FS-PHY-008
**Satisfies:** URS-PHY-006

### FS-PHY-009
**Satisfies:** URS-PHY-007
**Function:** Record a weight variation test (`record-weight-variation-result` for stage 1, `record-weight-variation-stage` for stage 2). After FS-PHY-002 (exactly one WeightVariation specification) the specification must have a dosage form. The settings come from the test definition and are these numbers when the test definition has none (CONF-093): unit count 20; tablet band 1 up to 130 mg at 10 %; tablet band 2 up to 324 mg at 7.5 %; tablet band 3 at 5 %; tablet maximum outside 2; capsule inner 10 %; capsule outer 25 %; capsule stage 1 maximum outside 2; capsule stage 1 maximum for retest 6; capsule stage 2 extra units 40; capsule stage 2 maximum outside 6. The settings are validated (counts at least 1, percentages above zero, band 1 limit below band 2 limit, inner below outer, stage 1 maximum outside below the retest maximum and the retest maximum not above the unit count, stage 2 maximum outside below the total units). The stage 1 list must have the unit count. Condition fields are checked as in FS-PHY-004. Tablet units carry only a weight above zero. Capsule units carry gross and shell weights, shell above zero and below gross. Tablets: the mean weight picks the band (mean not above band 1 limit uses band 1 percent; not above band 2 limit uses band 2 percent; else band 3); each unit's deviation is the absolute difference from the mean times 100 divided by the mean; a unit is outside when its deviation is above the band percent, and far outside when above twice the band percent; the result Complies when the outside count is not above the tablet maximum and no unit is far outside, otherwise DoesNotComply. A tablet test has no stage 2. Capsules at stage 1: for a HardCapsule form, if every unit's gross weight deviates from the mean gross weight by no more than the inner percent, the result Complies at once and the unit deviations stored are those of the gross weights. Otherwise net content (gross minus shell) is judged: a unit is inner-outside when its net deviation from the mean net is above the inner percent and outer-outside when above the outer percent. Any outer-outside unit gives DoesNotComply; otherwise inner-outside not above the stage 1 maximum Complies; not above the retest maximum gives NextStageRequired ("Stage 2 required"); more gives DoesNotComply. Stage 2 uses all units (unit count plus extra units), the mean of all net contents; any outer-outside unit gives DoesNotComply; otherwise inner-outside not above the stage 2 maximum Complies, else DoesNotComply. The reported value is the mean weight for tablets and the mean net content for capsules. The stage method requires NextStageRequired, a non-tablet form, exactly the extra unit count, and uses the settings and dosage form saved at stage 1. It rewrites the deviation and pass flag of every stage 1 reading against the combined mean, replaces the signature, entered-at time, comment, reported value, text, calculation text and status (CONF-092), and for SoftCapsule and HardCapsule alike skips the gross-weight shortcut. NextStageRequired adds no `Result` row and does not move the test order.

### FS-PHY-011
**Satisfies:** URS-PHY-008, URS-PHY-012
**Function:** Record a titration assay (`record-titration-result`). After FS-PHY-002 the method builds the configuration from the test definition (FS-PHY-010) and checks: the replicate count equals the configured count and each sample weight and titrant volume is above zero; a blank volume is required, and not negative, when the test uses a blank, and refused when it does not; a titration temperature is required when temperature correction is configured and refused otherwise; every specification has one of the result bases PercentAsIs, PercentDriedBasis, PercentAnhydrousBasis, PercentLabelClaim or MgPerUnit; an average unit weight above zero is required when any basis is PercentLabelClaim or MgPerUnit and refused otherwise; a typed loss-on-drying value is refused (see below); equipment, when given, must be of type Titrator, KarlFischer or Other. The titrant preparation must exist, belong to the test's section, be of the solution master configured on the test, and have the effective status Prepared (not expired or discarded); the same usability rule as FS-PHY-010 applies (the preparation's release approval status is not read, CONF-101); the titrant needs a nominal strength above zero and a current factor. Residual mode also needs the excess preparation by the same rules, and an excess preparation is refused in other modes. When the titrant (or excess) has a due warning the request must carry the acknowledgement flag and a justification of 10 to 500 characters (after trimming); a second signature with the meaning TitrantDueAcknowledged and the justification as comment is made before the result signature; an acknowledgement sent when there is no warning is refused. For the relative calculation, 1 to 3 standard titrations are required, all of the same standard lot, each weight and titre above zero; the lot must belong to the test's section, be a reference or working standard, have a recorded purity and pass `LotUsability.Check` (linked to the configured reagent, not awaiting release, not rejected, not expired, stock above zero and at least the quantity needed). The total standard weight in mg is converted to the lot's unit (grams: divided by 1000; kilograms: divided by 1,000,000; any other unit is refused). Calculation as coded: with temperature correction the volume V is replaced by V times (1 plus (standardisation temperature minus titration temperature) times the coefficient), where the coefficient is the test definition's expansion coefficient or 0.0011 when none is configured; the blank is corrected the same way. Net volume is volume minus blank for direct titration and blank minus volume for residual titration with a blank, and must be above zero. Direct: mg = net volume times nominal strength times factor times the equivalency factor (Karl Fischer uses 1). Residual without a blank: (excess volume times excess strength times excess factor minus corrected volume times strength times factor) times the equivalency factor, which must be above zero. Relative: for each standard, K = weight times purity divided by 100 times (100 minus the lot moisture, zero when none) divided by 100 divided by the net titre; the mean K is used and mg = net volume times K. Per specification and replicate the value is by basis: PercentAsIs is mg divided by sample weight times 100; dried or anhydrous basis multiplies that by 100 divided by (100 minus the moisture percent); PercentLabelClaim is mg divided by sample weight times average unit weight divided by the specification label claim times 100; MgPerUnit is mg divided by sample weight times average unit weight. The moisture percent for a dried or anhydrous basis is the sample's own result (FS-PHY-014): a dried and an anhydrous basis in one test is refused, a missing moisture result is refused, and a value typed by the analyst is refused. The result per specification is the mean of the replicate values; the relative standard deviation is the sample standard deviation divided by the absolute mean times 100 when there are 2 or more replicates and the mean is not zero. The mean is rounded to the larger of 2 decimals and the decimals of the specification's lower limit, upper limit, target and tolerance, and the rounded value is compared by `SpecificationEvaluator.Evaluate` (CONF-091). If the configured maximum relative standard deviation is set and exceeded, a WithinLimits status becomes RequiresReview; an OutOfSpecification status is kept. The titrant, standard, moisture and settings used are copied into the conditions text of the analysis. After the signature the standard lot's remaining quantity is reduced by the converted quantity in the same save, with the last-modified user and time set; no separate inventory ledger row is written by this method.
