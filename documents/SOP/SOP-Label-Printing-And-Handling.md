## 1. Purpose and scope

- Define how laboratory staff print, apply, inspect, reprint, and scan barcode labels generated by MicroLIMS for the six tracked record types: Samples (`S`, Code 128), Media lots (`MED`, Data Matrix), Solution preparations (`SP`, Data Matrix), Cryovials (`CRY`, Data Matrix), Material stock lots (`MAT`, Data Matrix), and Equipment assets (`EQ`, Code 128).
- Out of scope: uncoded records without an assigned identifier, external supplier barcodes not registered as the record code in MicroLIMS, and physical printer maintenance procedures.

## 2. Responsibilities

- **Operators (Analysts, Receiving Staff, Inventory/Equipment Staff):** Print first-time labels for records they create, verify physical print quality at 100% scale, affix labels cleanly, and use barcode scanning to confirm record selection during execution.
- **Section Heads / Authorized Reprinters (`Labels.Reprint`):** Review requests for additional or replacement labels, enter an accurate documented reason, and verify superseded damaged labels are destroyed or defaced.
- **Configuration Administrators (`Labels.Configure`):** Maintain approved label sizes (`WidthMm`, `HeightMm`), layouts (`Standard` or `Small`), and default copy counts (`Label Formats`), and confirm changes only after physical print-and-readback verification.
- **Quality Assurance (QA):** Approve this SOP, confirm retention and reconciliation rules, and sign off open manual verification gates and qualification records prior to production use.

## 3. Label formats and configuration

- Configure dimensions (`10` to `150` mm), layout (`Standard` or `Small`), and default copy count (`1` to `50`) in Laboratory Configuration -> Label Formats for each record type using actual site label stock specifications.
- Print generated label PDFs at **100% actual size** (no browser "fit to page" scaling) so barcode module widths (`0.25` mm minimum) and quiet zones (`10X` ends for Code 128; `1X` perimeter for Data Matrix) remain scannable.
- Once a label has been printed for an Equipment asset, its inventory code is locked in MicroLIMS and cannot be edited.

## 4. First-time printing

- Print first-time labels immediately from the post-creation print dialog or later from the record detail screen (`Print label`) using an account holding the record type's creation permission.
- Inspect printed labels visually before applying: verify the bold record code, print date, legible text, intact quiet zones, and flat placement on dry containers or instruments without wrapping barcodes sharply around small vials where distortion prevents scanning.

## 5. Reprinting and required reasons

- Any print request after a record's first logged print requires the `Labels.Reprint` permission and a clear, specific reason (`10` to `500` characters), such as `"Smudged thermal transfer print"` or `"Replacement label for damaged cryovial sleeve"`.
- MicroLIMS prints `REPRINT <n>` in bold on every reprinted label; verify the reprint number matches the replacement need and dispose of or deface any superseded label so two conflicting labels cannot remain in circulation.

## 6. Damaged, smudged, or illegible labels

- If a container or instrument label becomes damaged, smudged, faded, or fails scanner readback, stop using the item for testing until its identity is positively verified from primary MicroLIMS records (batch number, receiving record, storage location) and a controlled reprint is applied.
- Do not write unverified replacement barcodes by hand or continue workflow execution by overriding scan refusal messages unless following an approved QA deviation/contingency procedure.

## 7. Scanning practice and keyboard layout

- Use handheld barcode scanners in HID keyboard mode over USB or Bluetooth configured with an Enter (`CR`/`CRLF`) suffix, with the operating system keyboard set to **English**.
- If a scan is accidentally sent while Windows is set to the Arabic 101 keyboard layout, MicroLIMS converts unshifted Arabic characters and Arabic-Indic digits (`\u0660-\u0669`) and warns the operator (`Keyboard was in Arabic; the code was converted.`). Because shifted characters such as `:` and unmapped shifted Arabic symbols or `-` may not set the warning cleanly, operators must switch the OS keyboard back to English, verify the displayed target code in the UI, and re-scan if prompted.
- On workflow pickers, a scan selects an item only after the server confirms the expected record type, record usability (for example not expired, depleted, rejected, or awaiting release), workflow instrument linkage (for equipment), and presence in the step's offered list; treat any refusal alert as a hold check rather than forcing selection.

## 8. Camera scanning rules

- Where handheld scanners are unavailable on tablets or workstations over a secure HTTPS connection, staff may click the camera icon in Global Search or inline scan fields (`Data Matrix` and `Code 128` only).
- Hold the camera steady under adequate lighting until the first read registers (the stream stops automatically upon detection); if glare, curvature, or poor focus prevents readback, switch to a handheld scanner or manually verify and select the record per laboratory procedure.

## 9. What the print log proves and does not prove

- **What `LabelPrintLogs` and audit events prove:** That an authenticated user requested label PDF generation at a recorded UTC time for a specific record type, record ID, code, sequential print number, requested copy count, label format ID/version, batch ID, and (for reprints) documented reason. Database triggers block edits, deletions, and truncation of `LabelPrintLogs`.
- **What the print log does NOT prove:** Whether the browser or printer actually printed the PDF, how many physical stickers were produced or wasted during printer feed, whether every sticker was placed on the correct physical container or instrument, or whether the printed barcode passed scanner readback. Physical inspection and scan-to-select verification at use time provide those controls.

## 10. Records and retained evidence

- Electronic `LabelPrintLogs` rows and `LABEL_PRINTED` / `LABEL_REPRINTED` audit trail records (plus automatic `LabelFormat` change audit history) are retained in MicroLIMS as GxP records.
- Retained offline/Document Control records before release include signed qualification reports for `ZXing.Net` and `barcode-detector` / `zxing-wasm`, physical test-print readback sheets, and this approved SOP.

## 11. Open manual verification gates before go-live

- Confirm site printer model, print resolution (DPI), and physical label stock sizes for all six record types and update `Label Formats` defaults accordingly.
- Execute documented test prints at 100% scale on real stock and verify readback across all six record types using the site's actual handheld scanners and tablet camera, including an active Arabic keyboard layout test scan.
- Complete QA review, operational procedures (lost/extra label reconciliation, quarantine handling), and formal signatures below before moving this SOP from Draft to Approved.
